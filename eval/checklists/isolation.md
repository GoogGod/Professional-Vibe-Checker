# Чек-лист изоляции прогонов (Vibe Check)

Проверять перед каждой парой A/B. Результат отмечать в логе прогона (`isolation_check: ok`).

## Общее

- [ ] Свежий рабочий каталог на прогон: `runs/<batch>/<task>/<branch>/work/` (пустой, кроме входных материалов задачи).
- [ ] Внутри прогона нет доступа к каталогам других прогонов (пути не подсказаны, общего монтирования нет).
- [ ] Новая сессия/чат/контейнер на прогон; никакого общего состояния с предыдущими прогонами.
- [ ] Внешние сервисы задачи для пары A/B в одинаковом состоянии; пара запускается в одном временном окне.
- [ ] Версия пакета (коммит) зафиксирована и записана в логи; правки промпта/скиллов/базы в ходе серии не вносились.

## Ветка A (с пакетом)

- [ ] Подключён `package/system-prompt.md`; скиллы пакета доступны; база — read-only.
- [ ] Запись знаний — только в `<run>/knowledge-writeback/` (карантин; в базу не сливается до конца серии).

## Ветка B (контроль)

- [ ] Пакет физически недоступен: промпт пуст/стандартный, скиллы пакета не назначены, путь к базе не подсказан.
- [ ] В окружении ветки B нет даже имён скиллов/файлов пакета (ни в промпте, ни в подсказках).
- [ ] Проверка «на глаз»: если B-агенту дать команду «покажи свои скиллы» — пакетных не должно быть.

## Запуск

- [ ] Порядок A/B в паре случайный и зафиксирован в логах.
- [ ] Лимиты (время/шаги/токены) одинаковы для A и B и записаны.
- [ ] Транскрипт сохраняется целиком; любые вмешательства человека логируются (прогон помечается).

## После прогона

- [ ] Заполнен `run.md` (все метрики из PROTOCOL.md §7).
- [ ] Артефакты сохранены (`work/`, транскрипт).
- [ ] Карантин A не слит в базу (слияние — только после окончания серии).
- [ ] Пометки при необходимости: `invalid: true` (+причина), `contaminated: true` (задача пересекается с базой/библиотекой).

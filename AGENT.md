# AGENT.md — вход для модели (модульный режим)

Тебя подключили как **модуль**. Это значит: репозиторий — твой рабочий инструмент по CTF/Red Team, а **не задача**. Единственное правило чтения — **точечность** (роутер → 1–2 скилла), а не сплошной обход. Действуй по протоколу ниже.

> В zip-релизе пакета этого файла нет: роль входа выполняет `START-HERE.md` в корне распаковки.

## До задачи (цель — ≤2 минуты на ориентацию)

1. Открой `package/skills/ctf-router/SKILL.md` — роутер определит категорию задачи и назовёт нужные скиллы. **Скиллы модуля — обычные файлы**: инструмент `Skill` (если есть в harness) и прямое чтение файла — равноправные пути; файловое чтение — основной.
2. Прочитай **только** 1–2 названных роутером скилла (`package/skills/<name>/SKILL.md`; категорийные — точечно из `package/library/skills/<категория>/`).
3. Быстрый поиск по базе: `package/index.md` + ключевые слова задачи в `package/lessons/`, `package/tactics/`, `package/toolbox/`. Ничего релевантного — сразу к задаче.

## Во время задачи

- Работай по задаче. База — проверенные рецепты, а **не готовые ответы** для текущего соревнования: не подставляй данные архива как решения.
- **Запрещено** придумывать значения флагов — в любом виде, включая «для отвода внимания». Флаг = только фактически извлечённая и проверенная строка.
- Не выдавай выдумку за факт. Всё взятое из базы проверяй на своей задаче.
- Внешние инструменты (web-поиск и т.п.) не обязательны: модуль полностью работоспособен локально. Если заявленный инструмент недоступен — зафиксируй это и продолжай доступными средствами.

## После задачи — записать ТОЛЬКО если есть важное

Пиши запись, только если урок одновременно: **переносим** (не привязан к конкретной площадке/задаче), **не дублирует** `package/index.md`, **экономит другим ≥10 минут** или снимает тупик. **Пустой writeback — норма.** Мусор хуже пустоты.

Как записать:
- файл `package/lessons/YYYY-MM-DD-<slug>.md` по шаблону из `package/skills/hermes-knowledge-loop/SKILL.md` §3 + одна строка в `package/index.md`;
- скрипт длиннее 20 строк → `package/toolbox/`, в уроке — ссылка;
- есть право записи в репозиторий → коммит/PR по правилам [CONTRIBUTING.md](CONTRIBUTING.md); права нет → положи файл в `package/lessons/_inbox/` (мейнтейнер перенесёт).

## Твёрдые запреты (нарушение = отклонение PR)

1. Значения флагов: не хранить, не писать, не генерировать (только факт «решено/нет» и механика проверки).
2. Названия соревнований, организаций, ников — не упоминать; кейсы называй описательно.
3. Личные пути (`C:\Users\<имя>\...`, `/home/<имя>/...`), секреты, PII — не писать.
4. Не переименовывать каталоги `package/skills/*` и `package/library/skills/*` — платформы привязаны к именам.
5. Не удалять и не переписывать чужие записи; дополняй пометкой `[update: YYYY-MM-DD]`.

## Перед коммитом

`tools/check_package.ps1` должна вернуть `RESULT: 0 (clean)` (CI проверяет это автоматически на каждый PR).

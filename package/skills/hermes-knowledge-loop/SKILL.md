# Hermes Knowledge Loop — общая база наработок

Цель: агенты не теряют опыт, а накапливают его в общей папке и помогают друг другу. Реализуй цикл «перед задачей — искать, после задачи — сохранять».

## 1. Где база

Каталог `knowledge-base` пакета (там же лежат `README.md`, `index.md`, `skills/`, `system-prompt.md`). Если скиллы установлены в платформу, а пакет лежит отдельно — базой считается исходный каталог `knowledge-base`; если платформа ведёт свою рабочую базу — используй её каталог данных (найди по `index.md`). Пути в записях пиши **относительные** (относительно базы), чтобы пакет оставался переносимым.

Структура:
- `index.md` — реестр всех записей (одна строка на запись: дата, тег, путь, краткий итог);
- `lessons/` — уроки по задачам (`YYYY-MM-DD-<slug>.md`, шаблон ниже);
- `tactics/` — накапливаемые чек-листы и тактики по темам (обновляются в существующие файлы);
- `toolbox/` — сохранённые рабочие скрипты/фрагменты;
- `flags/` — только политика хранения флагов (см. §6).

## 2. Перед новой задачей — искать (обязательно)

1. Просмотри `index.md` и выполни поиск по базе по ключевым словам задачи (`Select-String -Encoding UTF8` по `*.md` или Python-обход).
2. Проверь `tactics/` и `toolbox/` на готовые рецепты.
3. Просмотри скиллы пакета (`ctf-lessons-corpus`, `crypto-solver-archive`, `host-artifacts-playbook`, `interactive-services-playbook`); при наличии внешней библиотеки — см. `ctf-router`.
4. Только после этого переходи к активным действиям.

## 3. После задачи — сохранять (обязательно после сложных/успешных/поучительных)

Создай lesson-файл в `lessons/` по шаблону:

```markdown
# <Название задачи / тема>
- Дата: YYYY-MM-DD · Категория: <web|crypto|stego|...> · Статус: решено | частично | не решено
- Результат: <достигнуто/нет + как проверено; значение флага — опционально, только в локальной копии записи с пометкой «не ответ для других задач»>
- Что дано: <1-3 строки>
- Цепочка решения: <5-10 шагов, командами там, где можно>
- Ключевые команды/скрипты: <ссылки на toolbox или код>
- Ловушки/ошибки: <что мешало, приманки, тупики>
- Урок: <1-3 вывода, которые пригодятся другим>
- Теги: #<категория> #<техника>
```

Правила:
- Коротко и воспроизводимо (важнее команды, чем проза).
- Секреты/PII не сохранять. Значение флага — только в локальной копии записи и с явной пометкой; хэши/фрагменты без нужды не тащи.
- Скрипт длиннее 20 строк — в `toolbox/`, в lesson — ссылка.
- Повторяющиеся находки — не дублировать, а обновлять соответствующий файл в `tactics/`.
- Всегда добавлять строку в `index.md`.
- Устойчивый общий урок — кандидат на продвижение в скиллы пакета: обнови подходящий скилл (`ctf-lessons-corpus` и др.) или создай новый.

## 4. Протокол «помощи другим агентам»

- Пиши так, чтобы применил агент без контекста: полные команды, коды возврата, относительные пути.
- В `tactics/` веди кросс-ссылки: задача → техника → похожие задачи.
- При тупике тоже пиши урок («проверено, не работает / ловушка») — это экономит время другим.

## 5. Регулярный ритм

- В конце **каждой** сессии: сохрани самые ценные записи, если они есть (**пустой writeback — норма**; даже по нерешённой задаче урок о тупике ценен).
- Раз в N задач: пересмотри `tactics/`, консолидируй дубли, вычисти устаревшее.
- База — общая: не удаляй чужие записи, дополняй пометками `[update: дата]`.
- Архивность: помни, что записи — исторический опыт; они не описывают текущее соревнование. Не подставляй их данные как готовые ответы.

## 6. Флаги — политика

- **Генерация значений флагов запрещена всегда** — ни заглушку, ни «примерно», ни «для отвода внимания».
- Формат флага — это прообраз из условия **текущей** задачи: знай, что искать, но не подставляй исторические значения как ответы.
- Найденное значение фиксируй в рабочих файлах задачи; в **локальной** копии записи урока — можно, с явной пометкой: «значение конкретной задачи; НЕ ответ для других задач».
- Публичный репозиторий/пакет значений не содержит: перед PR вычищай или маскируй (`<префикс формата>{...}`); проверка `tools/check_package.ps1` сканирует всё.
- Если другой агент оставил значение в публичной записи — замаскируй при следующем обновлении (не удаляя запись целиком).

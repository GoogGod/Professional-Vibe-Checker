# Attack/Defense CTF — готовность и тактика

Формат: у всех команд **идентичные** сервисы с уязвимостями; чекер каждый раунд кладёт флаги (put) и проверяет читаемость старых (get); очки за атаки (чужие флаги) и защиту (SLA своих сервисов). Один анализ сервиса работает на обе стороны: свой эксплойт на своём инстансе = эксплойт на всех командах, а найденная и закрытая у себя дыра = иммунитет. Конкретные числа сверяй с брифингом турнира — ниже профиль распространённого класса платформ (Forcad-подобные jury); персональный брифинг конкретного турнира ищи в `knowledge-base/local/` (П3).

## 0. Профиль платформы Forcad-класса

- **Ритм**: раунд ~60 с; флаг живёт ограниченное число раундов (типично 3–5) → **сдавать в течение 1–2 минут после кражи**, иначе сгорит.
- **Статусы сервисов**: OK / MUMBLE (отвечает, но логика частично сломана) / CORRUPT (чекер не может put/get) / DOWN. Всё кроме OK режет SLA.
- **attack_data API** (GET, обычно без авторизации): подсказки, где у каждой команды лежат актуальные флаги (имя пользователя, ID заказа, название заметки): `{"Service": {"10.80.1.2": ["hint1", "hint2"]}}`. Главный вход автоматизации — не перебирай сущности вручную.
- **submit API**: `PUT /api/v1/flags`, заголовок `X-Team-Token`, тело — JSON-**массив** строк флагов. Лимиты типичны: ~600 запросов/мин на источник, ~120 сабмитов/мин на команду; после пачки плохих флагов — slow-mode (задержка приёма). Значит: дедуп + валидация формата ДО отправки.
- **Volga-режим** (если заявлен): при не-OK **своего** сервиса флаги, добытые на этом же сервисе у других, не засчитываются → **защита приоритетнее атаки**; статус своих сервисов — под непрерывным мониторингом.
- **Сетевые окна**: первый час сеть обычно закрыта (чекеры не ходят, SLA не считается, атаковать нельзя) = чистое время на патчи и заготовки; возможен перерыв на обед с закрытой сетью (тоже окно для патчей).
- **First blood**: бонус за первую сдачу по конкретной уязвимости → в момент открытия сети скорость решает.
- **Scoring**: динамическая формула (дельта зависит от счёта атакующего и жертвы); инфляция; стартовая стоимость сервисов одинакова.

## 1. Подготовка (до старта)

1. **Инфраструктура по брифингу**: расшифровка командного архива (часто `age` — поставить заранее!), VPN (обычно openconnect; **один логин = один игрок**, параллельный второй VPN мешает), SSH на vulnbox (root; при капризах ключей `-o PreferredAuthentications=password`).
2. **Разведка сервисов**: карта каждого сервиса — точки входа, форматы ввода-вывода, состояние, админ-функции; кандидаты на уязвимости (инъекции, десериализация, IDOR, crypto-ошибки, парсеры).
3. **Понять чекер**: как флаг попадает в сервис (put), как извлекается (get), какие эндпоинты/форматы трогать НЕЛЬЗЯ. Сломанный чекер = потеря SLA, это дороже атак.
4. **Заготовки эксплойтов**: на каждую дыру — скрипт с контрактом `exploit(host, port, hints) -> flag|None`; тестировать на **своём** инстансе (образы идентичны).
5. **Свой инстанс-копия**: развернуть локально (docker) для безопасных экспериментов и «спарринга».
6. **Обвязка заранее**: молотилка (см. §5), submit-клиент с лимитами, watcher статусов, бэкап-скрипт.

## 2. Первый час закрытой сети (чек-лист T+0…T+60)

1. Подключение: VPN → SSH на vulnbox; проверить, что сервисы подняты (`docker ps`, порты).
2. **Полный бэкап ДО любых патчей**: tar сервисов + volumes + конфигов; снапшот перед каждым патчем (откат = mv, не «переписать заново»).
3. Прочитать код всех сервисов; для каждого: уязвимость + как чекер кладёт/читает флаг.
4. Патчи **маленькими шагами**: закрыл вектор → прогнал чекер-сценарий вручную (curl put/get как в §1.3) → снапшот. Один патч = один откатываемый шаг.
5. Эксплойты на найденные дыри — оттестировать на себе.
6. К моменту открытия сети: сервисы OK на scoreboard, молотилка крутится, первый эксплойт готов (first blood!).

## 3. Атака (после открытия сети)

- **Цикл молотилки** (каждые 60–120 с, в фоне): GET attack_data → для каждого сервиса × каждой чужой команды: `exploit(host, hints)` → флаги в очередь → батчем на submit (дедуп, валидация regexp формата из брифа).
- Эксплуатация **минимально достаточная**: забрал флаг — вышел. Не ломай чужие сервисы (штрафы/этика), никакого DoS.
- Эксплойт сломался → у жертвы патч; сравни с локальной копией образа, ищи новый вектор; фиксируй, кто закрылся (карта команд × сервисов).
- Ручные линии (новые дыры, реверс сложных сервисов) — параллельно с молотилкой: фоновые задачи/субагенты, результаты — в общий контракт `exploit()`.
- Slow-mode — враг: мусорных флагов в API не отправлять вообще.

## 4. Защита (непрерывно)

- **Volga**: свой сервис не-OK → добытое на нём сгорает → watcher статусов каждые 30–60 с + алерт; упал — сначала восстановление из снапшота (доступность!), потом разбор вектора.
- Патч не должен ломать чекер: сохраняй протоколы, эндпоинты и форматы данных; после каждого патча — свой put/get-тест.
- Флаг-гигиена: флаги не в логах/ошибках/листингах/world-readable файлах.
- **Перехват чужих атак**: логируй входящие запросы (access-логи сервисов, tcpdump на хосте) → чужой эксплойт против тебя = готовый вектор против всех остальных. Раз в несколько раундов разбирай лог на новые паттерны.
- На vulnbox не выключай VPN-клиент организаторов, не удаляй их SSH-ключи и мониторинг (вывод из игровой сети/потеря помощи).
- Секреты (токены, VPN-ключи, root-пароли) — не в публичные каналы и репозитории.

## 5. Автоматизация (скелеты)

- `farm.py` — цикл: attack_data → эксплойты (таймаут на каждый, ошибки в лог, успехи в очередь) → submit. Параллельность по командам (asyncio / ThreadPool / `xargs -P`).
- `submit.py` — очередь; seen-set на диске (переживает рестарт); regexp-валидация формата; батч ≤ лимита/мин; ретраи; лог ответов (accepted/rejected) для сверки со scoreboard.
- `watch.py` — scoreboard каждые 30–60 с; не-OK своего сервиса → файл-флаг + сообщение оператору (Volga-приоритет).
- Контракт эксплойта единый: `def exploit(host, port, hints) -> str | None` — молотилка не знает деталей, новый эксплойт = новый файл в каталог.
- Всё — фоновыми процессами с логами на диск; текущий статус линий — в `STATE.md`.
- Пример сабмита (сверь адрес/токен с брифингом):
  ```bash
  curl -sS -H "Content-Type: application/json" -H "X-Team-Token: $TOKEN" \
    -X PUT --data '["<FLAG1>","<FLAG2>"]' http://JURY/api/v1/flags
  ```

## 6. Этика и правила

- Атаковать **только** выданные инстансы соперников в рамках соревнования.
- Никакого DoS/флуда/удаления данных; не блокировать чекер; не трогать инфраструктуру платформы и служебные сегменты организаторов.
- Не сабмитить вне правил (окна сети, срок жизни флага, дубликаты).
- Инциденты — фиксировать и сообщать организаторам, если требуют правила.

## 7. Тренировка вне соревнования

- Скорость цикла «кража → сабмит» ≤ 1–2 мин — тренируй заранее на своём стенде.
- Патчинг: учебный сервис → закрыть уязвимости, не сломав функциональность (проверка «чекером» = скрипт put/get).
- Связка: этот скилл + `win-wsl-ctf-workbench` (окружение, PowerShell-триггер §1) + `hermes-knowledge-loop` (фиксация наработок между раундами) + `cve-scout` (фингерпринт версий в чужих сервисах).
- Запрещено тренироваться на реальной инфраструктуре без явного разрешения — только свои локальные копии и выданные полигоны.

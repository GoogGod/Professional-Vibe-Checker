# Attack/Defense CTF — готовность и тактика

Формат: несколько раундов, у каждой команды одинаковые сервисы с уязвимостями; в сервисах периодически обновляются **флаги**; очки за: (а) успешные атаки — флаги чужих команд (submit), (б) защиту — работающий сервис (SLA) и сохранность своих флагов. Формат — общий; конкретика определяется правилами конкретного соревнования, читай их.

## 1. Чеклист подготовки (до старта)

1. **Разведка сервисов**: получить исходники/бинарники (если выдаются), составить карту: точки входа, форматы ввода-вывода, состояние, админ-функции; отметить потенциальные уязвимости (инъекции, десериализация, IDOR, crypto-ошибки, парсеры, небезопасные форматы).
2. **Понять чекер**: как проверяется функциональность (`putflag` → как флаг попадает в сервис; `getflag` → как извлекается; что именно проверяет checker). Ошибки чекера → потеря SLA, это дороже атак.
3. **Заготовки эксплойтов**: для каждой найденной уязвимости — минимальный скрипт на Python (requests/pwntools), параметры: host, port, flag_id. Тестировать на **своём** инстансе.
4. **Свой инстанс**: скопировать себе, развернуть локально (docker/аналог) для безопасных экспериментов.
5. **Инфраструктура**:
   - скрипт-«молотилка»: пул целей, ретраи, дедуп флагов, отправка на submit-платформу;
   - watcher: логи, падения, кто и что трогает;
   - бэкапы файлов/конфигов своего сервиса перед каждой ротацией.
6. **Коммуникации**: таблица задач/эксплойтов/статусов (кто что ведёт), договорённость об этапах.

## 2. Тактика атаки (в каждом раунде)

- Порядок: (1) проверка своих эксплойтов на актуальность (сервисы меняют), (2) автоматический прогон по списку всех целей, (3) ручное исследование новых дыр, (4) не сломали ли наш эксплойт защитой соперника.
- Эксплуатация: только **минимально достаточная** (забрать флаг — выйти); не ломать чужие сервисы (fair-play; бывают штрафы).
- Флаги: сохранять (команда, раунд, сервис, значение, откуда); дедуп; сабмит немедленно (флаги истекают).
- Кросс-чек: эксплойт перестал работать — сравни с локальной версией сервиса, пойми, что изменилось.

## 3. Тактика защиты (в каждом раунде)

- **Патчинг**: закрывать уязвимости точечно, **не ломая функциональность чекера** (сначала прогони свой getflag/putflag-цикл!). Типовые патчи: валидация ввода, экранирование, верификация прав, отключение опасных фич. Патч должен пережить ротацию флагов и рестарты.
- **Флаг-гигиена**: флаги не пишутся в логи/ошибки/лишние ответы; не выдаются в листингах; не лежат в world-readable файлах.
- **Мониторинг**: доступность (SLA!), ошибки, подозрительные запросы; логируй действия атакующих (это ещё и материал для отчёта).
- **Против чужих эксплойтов**: валидация всех входов, канонизация путей, ограничение размеров; при необходимости — WAF/фильтры (осторожно, чтобы не триггерить чекер).
- **Оборона без паники**: сервис сломан — сначала восстановление доступности из бэкапа, потом закрытие вектора.

## 4. Автоматизация (наброски)

- Клиент-фреймворк на Python: `def attack(host, port, flag_id, префикс) -> flag|None` для каждого эксплойта; runner: очередь целей, короткие таймауты, ретраи, скрытие ошибок, печать только успехов.
- Submit-обвязка: очередь + лимиты частоты платформы; лог отправок.
- Мониторинг сервиса: периодический health-check, сравнение ответов с эталоном.
- Инструменты: pwntools, requests/httpx, nc/netcat, параллелизм (`xargs -P`, asyncio).
- Полезно: «спарринг» — развернуть свой сервис и атаковать себя (проверка эксплойта и чекера).

## 5. Этика и правила

- Атаковать **только** выданные инстансы соперников в рамках соревнования.
- Никакого DoS/флуда/удаления данных; не блокировать чекер; не трогать инфраструктуру платформы.
- Не сабмитить флаги вне правил; следить за политикой по своим/найденным значениям.
- Инциденты — фиксировать и сообщать организаторам, если требуют правила.

## 6. Тренировка вне соревнования

- Скорость раунда: сбор → сабмит ≤ несколько минут; автоматизация — заранее.
- Патчинг: возьми учебный сервис (свой или из открытых тренировочных архивов A/D-задач), найди и устрани уязвимости, не сломав функциональность.
- Отработка связки: этот скилл + `win-wsl-ctf-workbench` (окружение) + `hermes-knowledge-loop` (сохранение наработок после каждого раунда/сессии).
- Запрещено тренироваться на реальной инфраструктуре без явного разрешения: только свои локальные копии и выданные полигоны.

# CTF Router — диспетчер задач и знаний

Задача-роутер для офенсив-задач (CTF, учебный пентест, форензика). В начале задачи определи доминирующую категорию и работай по нужному чек-листу/скиллу.

## 0. Переносимость и источники знаний (важно)

- Этот скилл — часть переносимого пакета: все ссылки относительные. База знаний — каталог `knowledge-base` пакета (в нём лежат `README.md`, `index.md`, `lessons/`, `tactics/`, `toolbox/`). Если пакет установлен в платформу — база может лежать в её рабочих данных (найди по `index.md`).
- Библиотека категорийных скиллов — **внутри пакета**: `library/skills/` (каталоги вида `ctf-web`, `ctf-crypto`, `ctf-reverse`, `ctf-pwn`, `ctf-forensics`, `ctf-osint`, `ctf-misc`, `ctf-malware`, `ctf-ai-ml`, `ctf-writeup`, `solve-challenge` + вспомогательные `os-*`). Читай точечно (SKILL.md + 1–2 релевантных reference). Если пакет установлен на платформу и библиотека подключена отдельными скиллами — используй их; если недоступна — работай по разделу 3 и материалам пакета.
- **Архив ≠ текущая задача**: исторические кейсы и уроки — банк идей, а не ответы. Флаги в базе намеренно не хранятся; никогда не подставляй исторические значения как результат.

## 1. Триаж (первые 10 минут задачи)

1. Что дано: файлы / сервис / URL / текст? Сколько этапов явно (название, описание, теги)?
2. Определи доминирующий класс: web / crypto / reverse / pwn / forensics+stego / osint / misc / malware / ai-ml.
3. Зафиксируй из условия **буквально**: формат флага, лимиты попыток ввода, дедлайны, запреты.
4. Составь план из 3–7 шагов (TodoWrite) и заведи `STATE.md` в рабочем каталоге: цель, факты, гипотезы, следующий шаг.
5. Первое действие — разведка (файлы: `file`, exif, strings, binwalk; сервис: баннер, robots.txt, JS-ассеты). Никаких догадок без данных.

## 2. Индекс знаний пакета

- `knowledge-base/index.md` → реестр; `lessons/` — кейсы и разборы; `tactics/` — чек-листы по темам; `toolbox/` — готовые скрипты.
- Скиллы пакета: `ctf-lessons-corpus` (обобщённые приёмы и ловушки), `crypto-solver-archive` (крипто-рецепты), `host-artifacts-playbook` (Windows/память/трафик/диски), `interactive-services-playbook` (сокеты/боты/протоколы), `win-wsl-ctf-workbench` (окружение), `attack-defense-ctf` (A/D), `hermes-knowledge-loop` (сохранение опыта), `ida-workbench` (headless IDA), `stego-workbench` (стего-конвейер), `osint-workbench` (osint-конвейер: артефакт-паспорт, геолокация по чек-листу, фальсифицируемость гипотез), `revshell-arsenal` (обратные шеллы), `linux-privesc` (Linux privesc).
- Поиск по базе: текстовый поиск по `*.md` (PowerShell `Select-String -Encoding UTF8` или Python-обход).

## 3. Встроенный минимум по категориям (fallback, если библиотеки нет)

- **web**: маршруты/методы/параметры/заголовки; IDOR, SQLi, SSTI, LFI, SSRF, upload, JWT; исходники (sourcemap, `.git`), debug-эндпоинты; сравнение поведения с эталоном.
- **crypto**: определи схему (RSA/ECC/решётки/блочные/PRNG); малые/близкие показатели; общий модуль; nonce reuse; структура генератора; паддинги; валидация на синтетике.
- **reverse**: `file`/strings/детекторы упаковки; изолированный запуск; символы; динамика (Frida/x64dbg/gdb); сравнение трасс «ввод → вывод»; поиск проверок и сравнений. Есть локальная IDA — headless-разбор через скилл `ida-workbench`.
- **pwn**: откуда ввод, какие защиты (checksec), минимальный краш, примитив, эксплойт. Пост-эксплуатация: обратные шеллы — `revshell-arsenal`, Linux privesc — `linux-privesc`.
- **forensics/stego**: сигнатуры → метаданные → строки → структура; LSB/DCT/спектр/каналы; карвинг; таймлайны (UTC). Полный стего-конвейер — скилл `stego-workbench`.
- **osint**: артефакт-паспорт (EXIF/GPS/скриншоты) → геолокация по чек-листу признаков (номера, знаки, тени, инфраструктура) → поиск по нику/домену; фальсифицируемость: гипотеза = предсказания, 5+ независимых подтверждений. Полный конвейер — скилл `osint-workbench`.
- **misc**: кодинги, джейлы, SDR, паззлы; доводи результат до байтов и проверяй сигнатуры.
- **malware/ai-ml**: статический разбор без запуска на хосте; YARA; для ИИ-задач — prompt injection как класс данных.

## 4. Пивоты между категориями

- Бинарник/VM/фирмварь в основе → reverse; найденная в нём уязвимость → pwn.
- HTTP-баг как основной путь → web; если суть в крипто-примитивах (кастомные MAC, JWT-математика) → crypto.
- Логи/PCAP/дампы/стего → forensics; игровые/сокет-задачи → interactive-services-playbook.
- Смесь категорий → начинай со специфичной, misc — как fallback. RCE/футхолд — сначала `revshell-arsenal`, затем `linux-privesc`.
- ИИ-компонента (боты, LLM, ML) → ai-ml + заметки по prompt injection.

## 5. Анти-тупики

- Не закапывайся: нет прогресса за 3 итерации — смени гипотезу, перечитай условие буквально («что автор хотел сказать этой деталью?»).
- Веди учёт проверенных гипотез; тайм-боксы; независимые линии — в фон.
- Кандидатов-флагов проверяй на формат задачи и признаки приманок (см. `ctf-lessons-corpus` §1); не сдавай вслепую при малом лимите попыток.

## 6. Завершение

- Найден результат → зафиксируй артефакты (скрипты, команды, вывод), не правь задним числом; оформи мини-writeup.
- Сохрани урок в `knowledge-base/lessons/` (см. `hermes-knowledge-loop`); продвигай устойчивые уроки в скиллы.
- **Флаги не выдумывать ни при каких обстоятельствах** (в т.ч. «для отвода внимания»); в вывод — только фактически найденное и проверенное.

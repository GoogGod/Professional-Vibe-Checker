# CTF Router — диспетчер задач и знаний

Задача-роутер для офенсив-задач (CTF, учебный пентест, форензика). В начале задачи определи доминирующую категорию и работай по нужному чек-листу/скиллу.

**⛔ BOOT-ПРОТОКОЛ — каждый запуск, до первого действия с целью (первый curl/file/запуск/переход):**

- **П1. Карта возможностей (≤1 мин):** зафиксируй, ЧТО у тебя есть в этой сессии — доступные скиллы (листинг каталога), доступные инструменты (файлы, shell, сеть, субагенты, поиск, браузер), окружение (`win-wsl-ctf-workbench`). Работай только реальным; не изобретай инструменты и не жди того, чего нет.
- **П2. Маршрут:** доминирующая категория задачи → скилл из §2 → **прочитай его SKILL.md целиком** (Read). Имя в списке ≠ знание.
  **Категоризация ТОЛЬКО по сигнатурам (§1 п3а, §3): бинарник/ELF + интерактивное меню/сокет/приём ввода по частям = pwn (НЕ reverse); reverse — только для статического анализа без интерфейса взаимодействия.** Для pwn после SKILL.md ОБЯЗАТЕЛЬНО прочитай до 3 релевантных уроков фильтром `*pwn*`, `*menu*`, `*getc*`, `*vtable*`, `*uaf*` (сначала `local/lessons/`, затем `lessons/`).
- **П3. Чужой опыт (≤30 сек):** `knowledge-base/local/index.md` → `lessons/` → для web `local/toolbox/vuln-notes.md`. Поиск по реестру ВЕСТИ по ключам категории: pwn → `*pwn*|*heap*|*uaf*|*tcache*|*vtable*|*fmtstr*`; web → `*web*|*ssti*|*sqli*|*ssrf*|*idor*`; crypto → `*rsa*|*oracle*|*xor*`; и т.п. — не листай весь реестр подряд.
- **П4. План = TodoWrite:** П1–П3 первыми пунктами; точка «спросить оператора» для сенсорного (изображения/аудио/внешние аккаунты — кроп + один вопрос); точка «фиксация урока» в конце — только если задача сложная/многоступенчатая (при найденном флаге: СНАЧАЛА сохрани урок в `local/lessons/` + строку в `local/index.md` — защита от обрыва контекста, ПОТОМ итоговое сообщение оператору с флагом).
- **П5. Дисциплина исполнения:** код длиннее одной строки — файлом (Write), не инлайном; короткие WSL-команды — ЕДИНСТВЕННЫЙ рабочий паттерн: `wsl -d kali-linux -- bash -c "cd /mnt/c/<путь> && cmd | grep ..."` — все пайпы `|`, перенаправления `>`, кавычки `"…"` находятся ИСКЛЮЧИТЕЛЬНО внутри `bash -c "…"`; вне его — ни одного символа `|`, `>`, `<`, `&`, `"` (PowerShell их съедаёт/ломает; ловушки — `win-wsl-ctf-workbench` §1). Первая ошибка кавычек = немедленный уход на файл (Write) + запуск через `py_run`, а НЕ починка экранирования; для Python-скриптов по возможности используй инструмент `py_run` (минует оболочку полностью); ожидание внешнего события >15 мин — субагент или фоновый сторож с логом на диск (в чате фоновая задача Bash — уже параллельность; spawn_task — для длинных независимых веток); фингерпринт версии продукта → 30 секунд в `cve-scout` до погружения в логику приложения.
- **П6. Финал:** урок в `local/lessons/` + строка в `local/index.md` — только для сложных задач (простые: строка в `local/index.md` и хватит); обнови `vuln-notes.md`, если CVE-путь помог или опровергнут.

Пропуск протокола = повторение полевых провалов 2026-10-22 (5 мин до стены без чтения скилла; 256 сообщений соло; 7× кавычки; врайтбек в стираемую зеркалом зону).

## 0. Переносимость и источники знаний (важно)

- Этот скилл — часть переносимого пакета: все ссылки относительные. База знаний — каталог `knowledge-base` пакета (в нём лежат `README.md`, `index.md`, `lessons/`, `tactics/`, `toolbox/`). Если пакет установлен в платформу — база может лежать в её рабочих данных (найди по `index.md`).
- Библиотека категорийных скиллов — **внутри пакета**: `library/skills/` (каталоги вида `ctf-web`, `ctf-crypto`, `ctf-reverse`, `ctf-pwn`, `ctf-forensics`, `ctf-osint`, `ctf-misc`, `ctf-malware`, `ctf-ai-ml`, `ctf-writeup`, `solve-challenge` + вспомогательные `os-*`). Читай точечно (SKILL.md + 1–2 релевантных reference). Если пакет установлен на платформу и библиотека подключена отдельными скиллами — используй их; если недоступна — работай по разделу 3 и материалам пакета.
- **Архив ≠ текущая задача**: исторические кейсы и уроки — банк идей, а не ответы. Флаги в базе намеренно не хранятся; никогда не подставляй исторические значения как результат.

## 1. Триаж (первые 10 минут задачи)

1. Что дано: файлы / сервис / URL / текст? Сколько этапов явно (название, описание, теги)?
2. Определи доминирующий класс: web / crypto / reverse / pwn / forensics+stego / osint / misc / malware / ai-ml.
3. Зафиксируй из условия **буквально**: формат флага, лимиты попыток ввода, дедлайны, запреты.
   3а. **Название задачи ≠ тип.** Категорию и скилл определяй ТОЛЬКО по техническим сигнатурам (пути, заголовки, файлы, интерфейс), а не по имени сервиса/задачи. Имя может смениться — признак остаётся.
   3б. **Если таск лучше/быстрее решается человеком** (визуальные артефакты: картинки,
        фото, вывески, геймплей на экране, «человеческие» логики) — СРАЗУ запроси
        оператора с полным объяснением и контекстом, НЕ трать время на эмуляцию человека.
        Оператор — инструмент (правило 74). Всем шагам — дедлайны (75a), перед
        действием — анализ (75b), не повторять одно и то же >2-3 раз.
4. Составь план из 3–7 шагов (TodoWrite) и заведи `STATE.md` в рабочем каталоге: цель, факты, гипотезы, следующий шаг.
5. Первое действие — разведка (файлы: `file`, exif, strings, binwalk; сервис: баннер, robots.txt, JS-ассеты). Никаких догадок без данных.

## 2. Индекс знаний пакета

- `knowledge-base/index.md` → реестр; `lessons/` — кейсы и разборы; `tactics/` — чек-листы по темам; `toolbox/` — готовые скрипты.
- Скиллы пакета: `ctf-lessons-corpus` (обобщённые приёмы и ловушки), `crypto-solver-archive` (крипто-рецепты), `host-artifacts-playbook` (Windows/память/трафик/диски), `interactive-services-playbook` (сокеты/боты/протоколы), `win-wsl-ctf-workbench` (окружение), `attack-defense-ctf` (A/D), `hermes-knowledge-loop` (сохранение опыта), `ida-workbench` (headless IDA), `stego-workbench` (стего-конвейер), `osint-workbench` (osint-конвейер: артефакт-паспорт, геолокация по чек-листу, петля с оператором), `revshell-arsenal` (обратные шеллы), `linux-privesc` (Linux privesc), `browser-bot-bridge` (Web-задачи с ботами: postMessage-мосты, дроп-каналы, timing-оракулы, чек-лист финального замка), `cve-scout` (известные уязвимости по версиям: триаж «нужен ли CVE-путь», источники, учёт эффективности в vuln-notes.md), `ad-rehearsal` (предбоевая репетиция A/D на мок-жюри: связка farm+watch+эксплойты, Volga-учение).
- Поиск по базе: текстовый поиск по `*.md` (PowerShell `Select-String -Encoding UTF8` или Python-обход).

## 3. Встроенный минимум по категориям (fallback, если библиотеки нет)

- **web**: маршруты/методы/параметры/заголовки; IDOR, SQLi, SSTI, LFI, SSRF, upload, JWT; исходники (sourcemap, `.git`), debug-эндпоинты; сравнение поведения с эталоном; фингерпринт версии → 30 сек `cve-scout`. Есть бот-ревьюер/аудитор или XSS + закрытый маршрут — скилл `browser-bot-bridge`. **Сигнатуры WOPI/Collabora/офисного редактора**: пути `/wopi/files/*`, `/hosting/capabilities`, `/cool/ws`, `/cool/media`, `/browser/*/cool.html`, поля `WOPISrc`, `CheckFileInfo`, `BaseFileName`, `TemplateSource` ИЛИ интерфейс редактирования документов (.docx/.odt, «создать/сохранить/экспорт») → применяй универсальный рецепт **media traversal** (урок `office-libreoffice-wopi-media-traversal-solved`), не застревай на SSRF/convert-to. Маршрутизация выполняется ТОЛЬКО по этим признакам, а не по названию сервиса. **Сигнатуры крипто-оракулов**: `GET /public_key` (JSON n/e/ciphertext), `GET /oracle?ciphertext=` → `{"even":...}`, `POST /oracle {"msg":...}` → `{"block_xor":...}`, `POST /verify {"msg":...,"mac":...}` → применяй рецепты **RSA LSB**/**HMAC block_xor** из `crypto-solver-archive`, не перебирай «все атаки» вслепую. **Сигнатуры length extension**: multipart-форма с полями `sig_hex_*`/`msg_hex_*`, текст «sha256(secret || message)» или «secret = sha256(password)», логи со статусами ok/incorrect signature, гонка/список сущностей с действиями-правами по `user` → применяй рецепт **length extension** из `crypto-solver-archive`. **Сигнатуры визуального шифра**: PDF/изображение с сеткой эмодзи/форм/глифов + легенда (пары «символ→буквы») + таблица частот, флаг `hash(слово)` → применяй рецепт **визуальных шифров** из `crypto-solver-archive` (растеризация Form XObject → кластеризация → частотный анализ биграмм).
- **crypto**: определи схему (RSA/ECC/решётки/блочные/PRNG); малые/близкие показатели; общий модуль; nonce reuse; структура генератора; паддинги; валидация на синтетике.
- **reverse**: `file`/strings/детекторы упаковки; изолированный запуск; символы; динамика (Frida/x64dbg/gdb); сравнение трасс «ввод → вывод»; поиск проверок и сравнений. Есть локальная IDA — headless-разбор через скилл `ida-workbench`.
- **pwn**: откуда ввод, какие защиты (checksec), минимальный краш, примитив, эксплойт. Меню-сервисы: проверяй ВСЕ ветки switch дизассемблированием (скрытые пункты меню не видны в puts); если после `read()` в коде НЕТ `getc()`/`scanf()`-поглотителя — payload отправляй ровно len БЕЗ `\n` (урок `pwn-menu-read-getc-newline-trap`); для C++-объектов ищи перезапись vtable (урок `pwn-ruckzak-vtable-partial-overwrite`). Пост-эксплуатация: обратные шеллы — `revshell-arsenal`, Linux privesc — `linux-privesc`.
- **forensics/stego**: сигнатуры → метаданные → строки → структура; LSB/DCT/спектр/каналы; карвинг; таймлайны (UTC). Полный стего-конвейер — скилл `stego-workbench`.
- **osint**: артефакт-паспорт (EXIF/GPS/скриншоты) → геолокация по чек-листу признаков (номера, знаки, тени, инфраструктура) → поиск по нику/домену; фальсифицируемость: гипотеза = предсказания, 5+ независимых подтверждений. Полный конвейер — скилл `osint-workbench`.
- **attack/defense** (раунды, ротация флагов, jury/scoreboard, vulnbox, «сдать флаги в API») — скилл `attack-defense-ctf` (профиль класса jury/attack_data: attack_data, Volga-режим, лимиты сабмита, первый час патчей); конкретика турнира — в `local/` (брифинг); репетиция связки на мок-жюри — `ad-rehearsal`.
- **misc**: кодинги, джейлы, SDR, паззлы; доводи результат до байтов и проверяй сигнатуры.
- **malware/ai-ml**: статический разбор без запуска на хосте; YARA; для ИИ-задач — prompt injection как класс данных.

## 4. Пивоты между категориями

- Бинарник/VM/фирмварь в основе → reverse; НО с интерактивным меню/сокетом/вводом по частям — сразу pwn. Найденная в бинарнике уязвимость → pwn.
- HTTP-баг как основной путь → web; если суть в крипто-примитивах (кастомные MAC, JWT-математика) → crypto.
- Логи/PCAP/дампы/стего → forensics; игровые/сокет-задачи → interactive-services-playbook.
- Смесь категорий → начинай со специфичной, misc — как fallback. RCE/футхолд — сначала `revshell-arsenal`, затем `linux-privesc`.
- ИИ-компонента (боты, LLM, ML) → ai-ml + заметки по prompt injection.

## 5. Анти-тупики

- Не закапывайся: нет прогресса за 3 итерации — смени гипотезу, перечитай условие буквально («что автор хотел сказать этой деталью?»).
- Веди учёт проверенных гипотез; тайм-боксы; независимые линии — в фон.
- Кандидатов-флагов проверяй на формат задачи и признаки приманок (см. `ctf-lessons-corpus` §1); не сдавай вслепую при малом лимите попыток.

## 6. Завершение

- Найден результат → зафиксируй артефакты (скрипты, команды, вывод), не правь задним числом; оформи мини-writeup.
- Сохрани урок — **только в `knowledge-base/local/lessons/`** + строка в `knowledge-base/local/index.md` (формат — `hermes-knowledge-loop` §3). Публичная часть базы (`lessons/`, `index.md`, `toolbox/`) — read-only: её обновляет только мейнтейнер пакета, sync-зеркал удаляет чужие файлы оттуда. Продвигай устойчивые уроки в скиллы через оператора.
- **Флаги не выдумывать ни при каких обстоятельствах** (в т.ч. «для отвода внимания»); в вывод — только фактически найденное и проверенное.

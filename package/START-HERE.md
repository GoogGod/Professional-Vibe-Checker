# START HERE — переносимый пакет Red Team оператора

Это **самодостаточный пакет** для агента-офенсивщика: системный промпт + скиллы + база знаний. Пакет спроектирован так, чтобы работать автономно: все внутренние ссылки **относительные**, внешние ресурсы — опциональны, отсутствие остальной «материнской» системы ничего не ломает.

## Состав

```
knowledge-base/
├── START-HERE.md          ← этот файл
├── system-prompt.md       ← системный промпт агента (вставить в конфиг/системное сообщение)
├── README.md              ← краткое описание пакета
├── index.md               ← реестр записей базы знаний
├── VERSION                ← версия пакета
├── CHANGELOG.md           ← история изменений пакета
├── skills/                ← скиллы (agentskills.io-формат):
│   ├── ctf-router/                    # вызывать первым на любой CTF-задаче
│   ├── ctf-lessons-corpus/            # обезличенный корпус приёмов и ловушек
│   ├── crypto-solver-archive/         # архив крипто-солверов
│   ├── host-artifacts-playbook/       # Windows revers, память, трафик, диски
│   ├── interactive-services-playbook/ # сокеты, боты, крипто-протоколы
│   ├── win-wsl-ctf-workbench/         # окружение Windows/WSL/PowerShell
│   ├── attack-defense-ctf/            # готовность к Attack/Defense
│   └── hermes-knowledge-loop/         # петля самообучения (до/после задачи)
├── library/               ← библиотека категорийных скиллов (наследие; точечное использование):
│   └── skills/            # ctf-web, ctf-crypto, ctf-reverse, ctf-pwn, ctf-forensics, ctf-osint,
│                          # ctf-misc, ctf-malware, ctf-ai-ml, ctf-writeup, solve-challenge, os-*
├── lessons/               ← уроки и разборы кейсов
├── tactics/               ← чек-листы и тактики по темам
├── toolbox/               ← рабочие скрипты и заготовки
└── flags/                 ← только политика: флаги НЕ хранятся
```

## Быстрый старт

### Вариант A. Платформа с файловыми скиллами (например, Artex)

1. Скопируй каталоги из `skills/` в каталог скиллов платформы (Artex: `<корень установки>\skills\`; имена каталогов не менять).
2. Выдай нужные скиллы агентам в интерфейсе платформы (visibility) — платформа хранит назначения по **имени каталога** скилла.
3. Вставь содержимое `system-prompt.md` в промпт агента (или подключи как системное сообщение).
4. База знаний: оставь каталог `knowledge-base` рядом с данными платформы (платформа может использовать `data/knowledge-base`) — агент найдёт её по `index.md`.

### Вариант B. Любое агентское окружение

1. `system-prompt.md` → в системное сообщение агента.
2. Скиллы → агент читает файлы напрямую: первым `skills/ctf-router/SKILL.md` (маршрут), затем 1–2 названных скилла. Категорийная библиотека — `library/skills/` — так же точечно. Инструмент `Skill` в harness **не обязателен**: файловое чтение равноправно.
3. База знаний → используется по относительным путям от каталога `knowledge-base`.

## Железные правила пакета

1. **Флаги не хранятся** — ни в базе, ни в скиллах (исторические значения запрещены).
2. **Генерация флагов строго запрещена** — агенту запрещено придумывать значения флагов, в том числе «для отвода внимания». Флаг = только фактически извлечённая и проверенная строка.
3. **Архив — это архив**: кейсы и уроки описывают прошлые тренировочные серии и **не относятся к текущему соревнованию**; агент не должен путать текущую задачу с архивными.
4. **Переносимость**: никаких жёстких конечных путей; при переносе пакета ничего не переписывать в ссылках.
5. **Обезличенность**: названия конкретных соревнований и платформ не используются; кейсы названы описательно.

## Ритуал Hermes (обязательный для агента)

- **До задачи:** поиск в `index.md`, `lessons/`, `tactics/`, `toolbox/` по ключевым словам; просмотр релевантных скиллов.
- **После задачи:** записывай **только важные переносимые уроки** (пустой writeback — норма; мусор хуже пустоты): запись в `lessons/` по шаблону скилла `hermes-knowledge-loop`, строка в `index.md`, скрипты → в `toolbox/`, устойчивые приёмы → в скиллы.
- Тупики и отрицательные результаты — сохраняются, если переносимы и экономят время.

## Проверка целостности (для администратора пакета)

- В пакете не должно быть: значений флагов, названий конкретных соревнований, абсолютных путей пользователей (`C:\Users\...`, `/home/<user>/...`).
- Проверка: текстовый поиск по `knowledge-base/**/*.md` на подозрительные шаблоны (например, строки вида `{`...`}` с известными префиксами, имена пользователей, названия площадок).
- Если найден флаг, оставленный агентом, — удалить значение, оставив запись с пометкой «флаг удалён по политике».
- В `library/` допустимы учебные примеры из публичных разборов (плейсхолдеры вида `flag{...}`) и шаблонные пути (`C:\Users\<user>\...`); реальные значения флагов запрещены и там. Лицензионные заголовки файлов библиотеки сохранять.

## Обслуживание

- Раз в N задач: консолидировать `tactics/`, вычистить дубли, обновить скиллы.
- Не удалять чужие записи: дополнять пометками `[update: дата]`.
- При добавлении новых скиллов соблюдать правила 1–5 выше.

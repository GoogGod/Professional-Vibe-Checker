# PyInstaller-реверс «проклятого» байткода: скрэмблинг опкодов, блэкбокс-калибровка, инъекция сидкара

- **Дата:** 2026-10-23 (полевой solve, hard; 2 ч 08 м) · **Категория:** reverse / Python / PyInstaller
- **Ключевые слова:** PyInstaller, CArchive, code object, скрэмблинг опкодов, PYZ, fnv1a32, sidecar

## Стек задачи
PyInstaller onefile ELF, Python 3.13, code object `__main__` искажён: co_code ссылается на индексы вне диапазона, disassembly падает.

## Инструменты (которых нет — и что делать)
- `pyinstxtractor`/`xdis`/`decompyle3`/`uncompyle6` — не поддерживают Python 3.13. Писать своё.
- Свой экстрактор CArchive: magic `MEI\x0c\x0b\x0a\x0b\x0e`, TOC-записи (pos+c overlaid; грабли: `pyver=313` = 3×100+13, не версия файла).
- Толерантный дизассемблер: code object байт-за-байтом, co_exceptiontable как blob.

## Три «проклятия» и вскрытие
1. **Скрэмблинг опкодов**: порядок опкодов у каждой минорной версии 3.11+ свой (CACHE-операнды). Сломанный co_code = переставленные опкоды.
2. **Калибровка таблицы опкодов блэкбоксом** (главный приём): подаём микро-программы (только `LOAD_CONST`/`RETURN_VALUE` + один тестируемый опкод) в интерпретатор ЦЕЛИ (sidecar-режим), смотрим реакцию → восстанавливаем значение опкода измерениями, без догадок.
3. **PYZ-архив внутри**: zlib per-entry + TOC; короткие функции из `encodings.ascii`/`codecs` сравниваются с эталонными (локальный Python) → якоря той же таблицы опкодов.

## Sidecar-инъекция (когда декомпиляция бессильна)
Пересобрать валидный PyInstaller-архив с нашим code object как `__main__` (без onefile-компрессии) → МИКРО-программы прямо в интерпретаторе цели. Быстрее, чем подбирать опкоды по exe-диффам.

## Финал: constrain-solving вместо реверса логики
Массив `expected_hashes` (144× fnv1a32), `transform(ch)` — каждый символ флага независимо хэшируется и сверяется. Параллельный solver по позициям (перебор алфавита); 1 амбигентная позиция → вопрос оператору (префикс) → финальная строка проверена оригинальным бинарником.
**Урок:** per-symbol хэш-сверки → не реверсить поток управления, а решать систему ограничений; last-mile — вопрос оператору, не ещё час перебора.

## Грабли окружения
- `pip install pyelftools` не нужен — достаточно struct.
- WSLENV не переносится автоматически — пайпы unix-утилит только внутри `bash -c`.
- Короткие sha256-хэши не сходятся → это fnv1a32 (или другой 32-бит хэш), проверять до «сломанного sha256».

## Переносимое (в один абзац)
PyInstaller-цель на нестандартном Python = два реверса: формат (CArchive/PYZ — свой парсер ~200 строк) и интерпретатор (таблица опкодов — блэкбокс-микропрограммы, эталон внутри цели). Декомпилятор не нужен: sidecar-инъекция + решатель ограничений закрывают 90% таких задач.

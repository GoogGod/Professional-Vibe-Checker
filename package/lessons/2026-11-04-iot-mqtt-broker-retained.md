# MQTT/IoT: разведка брокера, креды и retained-флаг

Суть: IoT-задачи с MQTT-брокером (порт TCP). Цель — найти флаг
в топиках/сообщениях/сессиях.

## Разведка
1. Подключиться (Paho / raw сокет / mosquitto_sub), MQTT 3.1/3.1.1/5.
   - CONNACK Success — брокер жив, анонимный вход возможен.
   - Если CONNACK не Success — пробовать креды (см. ниже).
2. Подписка на `#`, `$SYS/#`, `$internal/#`, `+/+`, `+/+/+`,
   точные топики (flag/secret/topic/data/status/state/command/...).
3. Проверить **retained-сообщения**: `retain=True` у сервера
   (флаг часто именно в retained).
4. Проверить **Last Will / takeover**: подключиться с тематическими
   `client_id` (will-публикация при вытеснении сессии).
5. Проверить persistent session (clean_session=False): queue сообщений
   может содержать флаг.
6. MQTT 5: properties, TopicAlias, User Properties, ResponseTopic.

## Креды
- Попробовать анонимно → затем стандартные: `admin:admin`,
  `admin:password`, `admin:jennifer` (rockyou!), пользовательские пары.
- `admin:jennifer` — частая утечка из rockyou (специально подобрана).
- Проверять корректно: **после** connect() установить username/password,
  иначе ложный Success.

## Флаг
- В smartoffice-задаче флаг приходит немедленно после подключения с
  кредами: retained-сообщение в топике `smartoffice`.
- Команда для повторения:
  `mosquitto_sub -h [instance] -p [port] -u admin -P 'jennifer' -t 'smartoffice' -v -C 1`

## Если ничего не нашлось
Проверить, «маршрутизирует» ли брокер сообщения между клиентами:
A подписывается, B публикует — если A ничего не получает при PUBACK
Success от B, то брокер кастомный/урезанный или инстанс битый:
- сенсоры молчат; retained нет; $SYS молчит; команды без ответа;
- will не появляется; сессии пустые; креды не подобраны.
В этом случае, вероятно, инстанс восстановлен не полностью — пытаться
получить флаг стандартными MQTT-векторами бесполезно, надо либо
пересоздать инстанс, либо ждать рестарта и делать длинный пассивный
захват без активных команд.

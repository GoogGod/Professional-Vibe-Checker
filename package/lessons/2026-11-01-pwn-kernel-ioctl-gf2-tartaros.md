# Pwn: Windows kernel driver — ioctl + affine GF(2) + token patch (Tartaros)

Суть: драйвер ядра с IOCTL-обработчиком; уязвимость в алгоритме «аффинной»
функции над GF(2) → байпас проверки, затем патч токена.

## Предпосылки
- Исполняемый файл запускается внутри Windows VM (задача с SSH).
- Драйвер создаёт device, обрабатывает DeviceIoControl.

## Шаг 1. Реверс ioctl
- Определить: что копируется (METHOD_BUFFERED / METHOD_OUT_DIRECT), где читается
  пользовательский буфер, как транслируется.
- Функция F над GF(2): вход (например, 64 бита), выход проверяется против
  ожидаемого значения; «ядро» из 16 элементов — решение F(x)=target.

## Шаг 2. Байпас проверки
- Решить аффинную систему над GF(2) (XOR-уравнения) — можно перебором/Гауссом.
- Либо найти баг: METHOD_OUT_DIRECT→METHOD_BUFFERED подмена (copy_to_user)
  позволяет обойти проверку, записав ответ.

## Шаг 3. Патч токена
- В Windows kernel любые привилегии даёт токен процесса: патч
  SeBackupPrivilege (или SeDebugPrivilege) → чтение файла с флагом,
  который при обычных правах закрыт (protect).
- Или использовать поставленную функцию открытия файла с флагом «protect».

## Итог
- Для эксплуатации драйверов решайте математику проверки (GF(2) — просто),
  затем — либо обход через неправильный метод буфера, либо патч прав.

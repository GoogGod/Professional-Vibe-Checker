# Web: codec confusion + srcdoc + same-origin JSON-as-script (XSS)

Суть: пробел между кодировками (например, Shift_JIS и UTF-8) позволяет «выкрутить»
контрольные символы; валидатор видит одно, браузер исполняет другое.

## Паттерн (на примере бота/приватных заметок)
1. Сервис хранит заметки, открывает их ботом (owner cookie) и рендерит HTML.
2. Входной текст проходит валидацию и перекодировку (Shift_JIS → UTF-8).
3. Подберите байты так, чтобы после перекодировки появился тег/ASCII-символ,
   которого не было в исходном input (breakout из кодировки).
4. Когда вставка тега невозможна — используйте `<iframe srcdoc=...>`: содержимое
   внутри srcdoc исполняется в контексте страницы.
5. Отдавайте JSON с `Content-Type: application/json`, затем подключайте его как
   `<script type="module">` — модульный скрипт может исполнить JSON как код
   (same-origin + type=module обходит ограничения на JSON-ответы).
6. Цель — украсть cookie бота (document.cookie) или выполнить fetch на свои эндпоинты.

## Полезные уточнения
- Проверять: что именно считается кодом, а что данными (script src, import, srcdoc).
- Если фильтр режет «script» — пробовать другие теги/атрибуты и кодировочные замены.
- Публичные fallback-токены (BOT_UUID и т.п.) — частая причина утечки: если UUID
  известен из клиентского JS, доступ к приватным данным открыт без угадывания.

## Итог
- Всегда пробовать кодировочные атаки при наличии двух кодировок в цепочке.
- Проверять, не исполняется ли JSON как скрипт, и нет ли fallback-секретов в клиенте.

# Telegram-фишинг-воронка: Change.org-клон -> клон Telegram Web K (анализ и takedown-рекомендации)

## Контекст
Разбор двухступенчатого фишинг-кита, маскирующегося под «петицию» и воровства входа в Telegram. Авторизованный пентест. Урок не содержит адресов инстансов (заменены на [instance]).

## Признаки и сигнатуры
1. **Двухступенчатая воронка**
   - Ступень 1: лендинг-клон Change.org с «петицией», все кнопки ведут на клон Telegram Web (домен 2).
   - Ступень 2: полноценный клон Telegram Web K (официальный клиент, модифицированный).
   - Цель: жертва вводит номер телефона / код / пароль 2FA, т.к. считает страницу официальной.
2. **Конфиг встраивается в HTML base64-строкой** (поле `config` в localStorage/HTML):
   - `app_id=2040`, `app_hash=b18441a1ff607e10a989891a5462e627` — это публичный тестовый ключ GramJS (telegram.js). Такие значения используют самодельные киты.
   - поле `redirect` — финальная «чистая» ссылка (напр. telegra.ph), куда отправляют жертву после успеха.
3. **Статические ресурсы отдаются в уникальном хэш-каталоге** (меняется при каждой выдаче HTML), напр. `/<64hex>/<base64>/` — вызов `fetch` или JS с произвольными именами в нём невозможен (все несуществующие → 302 на Google).
4. **Анти-бот/маскировка**:
   - User-Agent, содержащий `HeadlessChrome` (или «необычные» UA) → 302 на **facebook.com** (лендинг) или **google.com** (клон). Обычный браузерный UA (Chrome/120+) → 200 и контент.
   - Любой несуществующий GET-путь → 302 на google.com (кликджекинг, чтобы сканеры не видели реальных маршрутов).
   - POST с `Content-Type: application/json` / `application/x-www-form-urlencoded` на **любой** путь → `{"result":"success"}` (глушилка/заглушка), даже для несуществующих URL.
   - Меняется и `base href` в HTML (свежий хэш при каждом запросе) — дефейс-ресурсы инвалидируются.

## Что искать при повторной встрече
- Сканировать **POST**-ом с JSON (не только GET) — так можно найти/проверить живые эндпоинты даже под маскировкой 302.
- Проверять GET с **обычным** браузерным UA (без HeadlessChrome) — контент отдаётся.
- Искать `app_id`/`app_hash` = 2040/b184... — это сигнатура «самодельного» кита GramJS.
- Проверять HTML на инлайн-base64 конфиг `{"hash":...,"domain":...,"redirect":...}`.

## Безопасность
- **Не передавать** на бэкенд реальные номера/коды.
- Не запускать скачанный JS на хосте без эмуляции — обфускация может делать внешние запросы; используй Playwright с подменой UA, перехватом, без реальных данных.
- При таймауте просмотра «скриншота» Playwright — не паниковать (страница блокирует screenshot), держи snapshot через `document.body.innerText`/DOM.

## Такедаун (рекомендации)
- Выявить хостинги: ASN/IP обеих ступеней (см. ipinfo.io/ip-api). Часто это **разные** хостинг-провайдеры (напр. FEMO IT Solutions, Local NCC).
- Подать абьюз-репорты обоим хостерам (фишинг/вредоносный сайт) + регистратору/NS хостеру (Wix DNS).
- Рекомендация жертвам: принудительный выход из сессий Telegram и смена пароля.

# Урок: первый Attack/Defense — как взять first blood и не слить день

Дата: 2026-10-25 · Категории: attack/defense, process, ops · Исход: середина таблицы при пике топ-3; потери кратно превысили кражи
Детали/полная хронология: `local/tactics/ad-field-notes.md`

## Суть: стабильность > взлом
Проиграли не потому, что не вскрыли сервисы (вскрыли быстро: 2 из 4, first blood на 3-й мин), а потому что свои падали и кормушка была открыта полдня. A/D выигрывается стабильностью.

## Главные правила (проверено кровью)
1. **Preflight за день до старта**: sshpass установлен, ключ сгенерирован, репетиция VPN-демона (`setsid nohup`), скрипты vpn_start/farm написаны. Подключение на турнире съело 42 мин — всё лечится заранее.
2. **Атака**: farm.py поднят ДО сети (first blood), эксплойт-контракт `exploit(host,port,hints)->[flags]`, субагенты на сервисы, реальные имена из `/api/client/tasks/` (не из брифа), watch.py алерт по статусам.
3. **Петля сгорания**: свой сервис не-OK → нет hints → 0 флагов с линии + сгорают добытые. SLA важнее любого эксплойта. Не-OK после патча = немедленный откат.
4. **NAT**: весь входящий с одного IP — баны по IP запрещены, различие чекер/атакующий только по поведению (лучше не различать).
5. **Дренаж**: свои дыры закрывать В ТОТ ЖЕ ЧАС (L1-канализация: переместить/зашифровать хранилище флага). Каждая найденная уязвимость = готовый эксплойт против всех.
6. **Ферма — стадо**: мёртвая линия (N циклов→0 флагов) отключается без сожалений; seen-файл на диск (дедуп); свои флаги не сабмитить.
7. **Мелочи**: pids-limit в compose (а не в рантайме), лаборатории не на vulnbox, бэкап до первого патча (исходники, не образы), главный чат чистый (тяжёлое — субагентам).

## Как это выглядело
66 М входных токенов, 325 Bash, 8 субагент-задач, first blood + рабочий пайплайн с первой минуты. Проигрыш тактический, устранимый.

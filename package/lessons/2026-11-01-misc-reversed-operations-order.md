# «Перепутанный порядок операций» (реверсивный шифр)

Суть: автор «закодировал сообщение» (например, base64/xor/hex), но перепутал
порядок действий — восстановление возможно через системный перебор вариантов.

## Методика
1. Разложить данные на примитивы: hex → байты; `base64(данные)` — читаемый текст.
2. Если кодба64` даёт читаемую строку с leet/«мусором» — это почти всегда
   ключ к восстановлению: заменить символы из алфавита base64 на символы
   флага (`+`→`{`/`}`, `/`→`_`).
3. Комбинировать примитивы (xor/base64/reverse/hex) в разных порядках; для
   каждого проверить, не является ли результат читаемым флагом.
4. Известный префикс (`ПЛАТФОРМА{`, `ПЛАТФОРМА{`) — фильтр; перебор малых
   пространств ключей/длин — быстро.

## Пример (обобщённый)
- Пусть `base64(data)` = `ПЛАТФОРМА+<leet1>/<leet2>/<leet3>+` (читаемая строка).
- Это подсказка: заменить символы алфавита base64 на символы флага
  (`+`→`{`/`}`, `/`→`_`); leet-слова внутри часто читаются как
  `reverse` / `base64` / `task` — прямое указание на операции.
- Всегда финально проверять флаг: `ПЛАТФОРМА{...}`.

## Грабли
- Не искать «универсальный алгоритм»: читать символы/лексику в выводе.
- Если BFS-перебор разросся — ограничить глубину и проверять префикс/суффикс.

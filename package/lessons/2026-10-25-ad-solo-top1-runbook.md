# Урок: ранбук соло-топ-1 для Attack/Defense (из чего реально складывается первое место)

Дата: 2026-10-25 · Категории: attack/defense, process, strategy · Основа: полевой день A/D + разбор его цифр

## 0. Формула топ-1 (выведена из наших же цифр)

Итог дня: потери флагов кратно превысили кражи, SLA неполный, пик в топ-3. Пересчёт «что если»:

| Фактор | Было | Надо для топ-1 | Цена |
|---|---|---|---|
| Потеряно флагов | много (кормушка открыта полдня) | мало (закрыть в первый час) | кратно больше |
| SLA | неполный | 4 × ~98–100 | база очков каждый раунд |
| Живые линии | половина (остальные голодали) | 3–4 весь день | флаги каждый раунд |
| Скорость кражи | кое-как | первые секунды раунда (round-sync) | «already stolen» → нам |

**Топ-1 = SLA 4×100% + ноль дренажа + 3–4 живые линии + скорость первого часа.** Всё остальное (красивые 0day, реверс) — вторично. Победитель турнира почти наверняка не был лучшим взломщиком — он был самым стабильным.

## 1. Почасовой план соло (главный чат = mission control)

- **T-1 день**: репетиция на `toolbox/ad/mock_jury.py` (см. §8) + preflight-чеклист скилла.
- **Первый час игры (сеть закрыта)**: подключение ≤10 мин (sshpass → ключ, VPN-демон `setsid nohup`); реальный список сервисов из `/api/client/tasks/`; **checker-first по каждому сервису (§2)**; бэкап исходников; один простой сервис размечен под first blood; farm/watch подняты и rehears-проверены на live-API; ЛАБОРАТОРНЫХ контейнеров на vulnbox нет.
- **Следующий час (атака открыта)**: farm непрерывно; первый эксплойт в бой немедленно, без полировки (first blood); анти-дренаж watch слушает `/public/attacks`; каждые 10 мин — сводка одним абзацем (не логами!).
- **Третий час**: закрывать СВОИ найденные дыры (к этому моменту дренаж-данные показывают, какие именно доят у всех); патч-таксономия §3; каждый патч — чекер-тест → снапшот.
- **Обеденная пауза (сеть закрыта)**: глубокий RE сложного сервиса (субагент), рискованные патчи с полным тестом, заготовка новых эксплойтов. Никакого ожидания.
- **Послеобеденное время**: расширение линий: майнинг `/public/attacks` (чужие команды в логе = готовые векторы против ещё не закрывшихся), tcpdump на своём боксе → реплей чужих атак = новые эксплойты.
- **Предфинальный отрезок**: экономика линий §5, стабилизация, добивка SLA до 100%.
- **Последний час**: **никаких изменений** — заморозка. Только кража и сабмит.

## 2. Checker-first (главный недостающий навык этого турнира)

Мы читали код сервисов «на общих основаниях» и теряли часы. Правильно: **чекер — это карта хранения флагов**.

1. Сразу после подключения: `/public/scoreboard/teamtasks/<своя-команда>/<task>/logs` — шаги чекера (какие эндпоинты, в каком порядке, что кладёт/читает).
2. Для каждого сервиса ответь письменно: «чекер кладёт флаг через X, хранит в Y, hint в attack_data = Z» (Z обычно = ключ поиска: имя пользователя/ID/тайтл).
3. Это знание одновременно: (а) половина эксплойта (знаешь, где искать), (б) spec для патча (что нельзя ломать), (в) чекер-тест для каждого патча.

## 3. Патч-таксономия (выбор уровня — по времени и риску)

- **L0 Откат** — статус важнее: мгновенно, дыра открыта. Применять при не-OK после патча, без раздумий.
- **L1 Канализация** — не закрывать дыру, а лишить её добычи: переместить/переименовать/зашифровать хранилище флагов, рандомизировать ID. Чекер обычно доволен (легитимный путь цел), атакующий эксплойт ломается об изменившееся хранение. **Дефолт для соло: быстро, дёшево, безопасно.**
- **L2 Точечное закрытие** — валидация ровно в месте вектора (не «на входе всего» — сломаешь чекера). Требует чекер-теста.
- **L3 Ре-архитект** — никогда в игре (только на обеде, и то вряд ли).
- NAT-реальность: весь входящий с одного IP → **никаких IP-банов**; различие чекер/атакующий только по поведению — а лучше вообще не различать (§уровень L1 закрывает без различения).

## 4. Анти-дренаж: зелёный статус ≠ нас не доят

Полдня нас drained при OK-статусах (оператор заметил по scoreboard слишком поздно). Правильно:
- `watch.py` v2 считает `flag_stolen`-события против нас из `/public/attacks` каждый раунд; порог 3+/раунд → DRAIN-алерт с именем сервиса;
- DRAIN-алерт = приоритет №1 (выше любых новых векторов): L1-канализация кормушки;
- периодически сверять «у кого мы крадём» с «у кого крадут все» — если линия даёт «already stolen» >50%, все уже закрылись или обгоняют: линию в пенсион.

## 5. Экономика линий (ферма — стадо, не музей)

- Метрики линии: попытки / флаги / «already stolen»% / средняя длительность. Линия с 25+ попытками и 0 флагов — балласт (она стареет чужие флаги в очереди) → RETIRE.
- Round-sync (`/api/v1/ctftime`): кража в первые секунды раунда — чекер положил флаг, ты первый. Середина раунда = «already stolen».
- Новая линия от субагента = файл в `exploits/` + рестарт фермы; ферма не знает деталей (контракт `exploit(host, port, hints)`).
- Соло ≠ один эксплойт за раз: 2–3 простых линии весь день лучше одного красивого реверса к концу дня.

## 6. Командирский цикл соло (как не сжечь оператора и контекст)

Поле: 66 М входных токенов, 3 переполнения контекста, ~30 «продолжай» от оператора. Для соло это главный риск.
- Главный чат = **mission control**: решения и сводки; всё тяжёлое (чтение кода, реверс, дебаг) — субагентам (`spawn_task` по сервису); в чат — только выводы.
- Каденция: каждые 10–15 мин сам пишет однострочную сводку (score, статусы, линии, дренаж). Оператор читает, не дёргает.
- `STATE.md` на диске — единственный источник правды после переполнения контекста: карта сервисов (уязвимость/патч/эксплойт/статус), пути, открытые вопросы.
- Эскалация оператору — только решения (какой сервис патчить, рисковать или нет), не процесс.
- Фоновые демоны переживают всё: `setsid nohup` (ферма, watch, VPN) — чат может умереть, они нет.

## 7. Архетипы сервисов (шпаргалка первого часа)

| Архетип | Узнать по | Типовые баги | Первый патч (L1/L2) |
|---|---|---|---|
| CRUD-хранилище (notes/greenhouse) | REST, сущности, поиск | проекция/подстрочный поиск, IDOR, SQLi в фильтре | убрать проекцию закрытых полей; канализировать хранение флага |
| JWT/сессии (starpost) | токен в куке, /login | none-alg, слабый секрет, предсказуемая сессия, IDOR по ID | проверить алг/секрет; серверная проверка владельца |
| Парсер (orbital, Rust/Go) | бинарник/стрик, форматы | паники (unwrap) на кривом вводе, integer, логика статусов | гвард-клаuses на ввод; не рефакторить в бою |
| Гонка/окно (lighthouse) | «первым успел», TTL, очередь | TOCTOU, race за слот, off-by-one | сначала математика: если чекер всегда первый — это не вектор, а ловушка (потеряли десятки раундов) |

Правило: 15 минут на классификацию сервиса, потом решение «копаем / откладываем / пропускаем». Гонки без доказательства преимущества — в пропуск.

## 8. Репетиция T-1 день (mock_jury — обязателен, 5 минут)

`toolbox/ad/mock_jury.py` поднимает jury-API + 2 уязвимых сервиса + чекер. Прогнать: ферма крадёт и сдаёт (виден «Flag accepted!»), watch видит статусы; `POST /admin/patch` → CORRUPT-алерт (петля сгорания руками), `/admin/rollback` → OK; отключить один эксплойт — ферма жива. Если канвейер прошёл на моке — в бою он не удивит. Детали — `toolbox/ad/README.md`.

## 9. Мораль

Соло-топ-1 — это не «взломать всех», это **непрерывность**: ферма и вахтёр не спят, сервисы не падают, кормушки закрыты в первый час, а оператор читает сводки и принимает по три решения в час. Автоматизация + стабильность + дисциплина таймлайна; всё остальное приложится.

# PWN: fmtstr + переполнение, один вызов vuln — разбор полного решения

## Задача (обезличенно)
ELF64, Partial RELRO, NO PIE, no canary. vuln вызывается один раз:
fgets(buf, 0x190, stdin) + printf(buf) + putchar('\n') + leave/ret.
Буфер 0x70, offset до ret = 0x78. Main вызывает vuln один раз; после vuln печатает "Goodbye!" и выходит. Смещения: vuln=0x4011d6, main=0x401236, ret-гаджет (в конце vuln)=0x401235, GOT[printf]=0x404030.

## Ключевые факты (подтверждены экспериментально)

### 1. Повторный вход: проблема выравнивания стека, а не rbp
- Первый ret->MAIN/ret2vuln работает, второй — нет (EOF, SIGSEGV).
- gdb: крах внутри glibc `__vfprintf_internal` на `movaps %xmm0,0x40(%rsp)`.
- Причина: вход через `ret` (без `call`) сдвигает кадр на 8 байт; rsp%16=8 → movaps падает.
- Решение: добавить ПРОМЕЖУТОЧНЫЙ RET-гаджет (0x401235) перед целевым адресом:
  `saved rbp | RET | TARGET` — тогда следующая функция получает выровненный стек.
- После этого мультицикл стабилен (5+ проходов).

### 2. Leak адреса: NUL-обрезка
- `%12$s` печатает содержимое GOT как строку — обрезается на первом NUL (часто байт 3-5).
- На одном из инстансов адрес printf обрезался до 2 байт: 0xa6f0.
- Надёжный leak: печатать по одному байту: `%12$s|%13$s|%14$s|%15$s|%16$s|%17$s|`, положив указатели на GOT+0..5 на позиции 12-17; первый символ каждого сегмента = байт адреса (0, если сегмент пуст).

### 3. Определение libc
- Абсолютные адреса из РАЗНЫХ подключений нельзя сравнивать (KASLR меняется между соединениями). Дельты — только из одного процесса.
- На целевом инстансе libc оказалась glibc **2.35-0ubuntu3.18** (printf=0x60680, system=0x50d00), хотя в базе ожидалась 2.35-0ubuntu3 (printf=0x60770, system=0x50d60). Порядок puts/setbuf в memory-map отличался от всех локальных кандидатов.
- Метод: по-байтовый leak нескольких функций в одном процессе → дельты; если профиль не находится — брутфорс кандидатов: для каждого перезаписать GOT[printf]=base+system и проверить триггером `echo MARKER; id`.

### 4. Финальная связка (3 прохода)
1. Проход 1: leak printf (`%12$s|` + адрес GOT в хвосте) + RET+MAIN.
2. Проход 2: `%hhn`-перезапись трёх младших байтов GOT[printf] → system + RET+MAIN.
   Счётчики: первое значение печатается как `%Nc` от 0, далее `%Nc` с добавкой (mod 256).
   Формат: `%96c%12$hhn%125c%13$hhn%167c%14$hhn` — длина < 48, адреса на позициях 12-14.
3. Проход 3: отправить команду (например `cat flag`) — vuln вызовет `system(buf)`.

## Анти-тупики
- Не верить «стандартному» профилю libc без проверки — идентифицировать по дельтам в одном процессе.
- NUL в адресе ломает строковый leak — собирать по байтам.
- Повторный вход падает из-за SSЕ-выравнивания — лечится RET-гаджетом.
- fmtstr_payload может генерировать длинные строки; писать короткие `%hhn`-цепочки вручную.

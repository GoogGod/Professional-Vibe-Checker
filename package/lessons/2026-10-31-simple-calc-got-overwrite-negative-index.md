# 2026-10-31: платформа «Простой калькулятор» (PWN easy) — GOT overwrite через отрицательный индекс

Бинарник: `simple_calc` (ELF x86-64, EXEC/no-PIE, partial RELRO, NX, без канари).

## Суть

`add_value` пишет `nums[idx] = val`, где `nums=0x404080`, а индекс проверяется **только сверху** (`idx <= 1000`) — отрицательные разрешены.
`nums[-16]` = `0x404080 - 128 = 0x404000 = puts@GOT` (`.got.plt` writable) → записать туда `system@plt (0x401040)` → все `puts` становятся `system`. Триггер: меню `5` (greet) → `puts(buf)` → `system(buf)`.

## Ловушки

1. **`scanf("%128s")` читает ОДНО СЛОВО.** Команда с пробелами (`cat /app/flag`) разбивается: первое слово уходит в `system()`, остальное застревает и съедается следующими вызовами `scanf`. Решение: редирект без пробелов — `cat<flag` (или `cat</app/flag`). Это была главная причина «неудачи» первых попыток — GOT-перезапись работала всегда.
2. Локальный тест сработал, remote нет → паника рано. Диагностика: краш-тест мусором (слепой), затем скан индексов -24…-12 с `ls` подтвердил idx=-16 (system("ls") вывел листинг `/app`).
3. `giiift` даёт утечку `printf@GOT` — не обязательна (system@plt — фиксированный адрес).

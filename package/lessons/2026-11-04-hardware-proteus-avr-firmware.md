# Proteus 8 + AVR: разбор проекта САПР и прошивки (Intel HEX)

Суть: hardware-задача с проектом Proteus 8 (`.pdsprj`) и прошивкой
ATmega32 (`code.hex`). Флаг скрыт в данных flash и выводится при
аварийном сценарии.

## Шаг 1. Распаковать проект САПР
- `.pdsprj` — на самом деле **ZIP**: распаковать (`7z x` / `unzip`).
- Внутри: `ROOT.DSN` (схема, бинарный, но строки/свойства читаются
  парсером `\xff-len`), `ROOT.CDB`, `GRAPHS.DAT`, `ROOT.LYT`, `PROJECT.XML`.
- Из `ROOT.DSN`/XML вытащить: микроконтроллер (ATmega32, частота),
  датчики/шины (I2C: LM75AD; SPI; UART), подтяжки/resistors.

## Шаг 2. Дизассемблировать прошивку
- `avr-objdump -D -m avr5 code.hex` (или `avr-objdump -D code.hex`).
- Найти `main` и ветки: инициализация UART/TWI, цикл опроса датчиков,
  чтение температуры (2 байта по I2C).
- Особое внимание блокам условной печати: при выходе значения за
  диапазон (`< -1000` или `>= 128`) программа печатает ALERT и
  «зависает» — там выход на скрытую строку.

## Шаг 3. Ключевой приём: скрытый массив + XOR
- Из flash по адресу начала данных скопировать N байт (обычно это
  строки/скрытый массив, копируемый в SRAM при старте).
- Перебрать однобайтовые XOR-ключи (0x00..0xFF) — при совпадении
  получится читаемый текст, содержащий флаг.
- Пример: 36 байт данных XOR 0x42 → флаг.

## Грабли
- «HEX не влияет» — отвлекающий манёвр: прошивка всё равно читается,
  флаг именно в данных прошивки.
- Не доверять букве задачи: «условие» может быть ложным (dummy).
- Формат `code.hex` — Intel HEX; кроме objdump можно использовать
  `hex2bin` и уже бинарно искать строки.

# Урок: strange_winapi — хуки, детуры PRNG и инверсия блочной трансформации

Платформа: «платформа». Бинарник: PE64 (MSVC Debug, `.CRT$XCU` → install_hooks, MinHook).
Реверс-задача. Флаг формата `DUCKERZ{...}`.

## Суть задачи
Программа перехватывает MessageBoxA и внутри хука выполняет проверку «флага»:
- Buffer = `a1 + *(DWORD*)a1 + 0x68` (где a1=&pe, dwSize=568 → v14, буфер ввода 64 байта);
- Key = 4 байта из стека хука = 4-й аргумент MessageBoxA (`v20 = a4`);
- `SystemFunction033` из advapi32.dll = классический RC4 (сверено с эталонной реализацией);
- `memcmp(buffer, &etalon(0x140014D10), 0x40)` → «It's fine» / «It's bad».

До проверки вход обрабатывается детурами `Process32FirstW`/`Process32NextW` (MinHook):
- FirstW: создаёт `std::mt19937` с seed `0x1337` (4919), берёт 16 значений PRNG,
  `idx = rand % NumberOfFunctions` из Export Directory kernel32, копирует последние 4 байта
  «строки» из машинного кода экспортной функции в буфер (16 DWORD);
- NextW: для каждого процесса применяет к i-му DWORD буфера:
  `out[i] = 0x1337 * ((buf[i] ^ key_i) + 0xAB0BA11) mod 2^32`, где key_i — 4 байта имени процесса.

Ключевая особенность: итоговая схема **блочно-независима** — `out[i]` зависит только от `in[i]` (DWORD).
Это позволяет инвертировать поиск: для каждого блока решается
`in[i] = (((target[i] * inv(0x1337)) mod 2^32) - 0xAB0BA11) ^ key_i`.

## Как решать
1. Использовать отладчик (CreateProcess + DEBUG_PROCESS), патчить спинлок `_Init_thread_header` → `C3`;
   байт ввод через pipe (`STARTF_USESTDHANDLES`).
2. Поставить 0xCC на адрес `call SystemFunction033` (в этом бин `0x1400034F1`):
   читать буфер (64), ключ (4), эталон (64). Адрес «после вызова» — `0x1400034F8` (не 0x4F7!).
3. Получить эталон E и ключ K; вычислить цель `T = RC4(K, E)` — это содержимое буфера,
   которое должно получиться ПОСЛЕ детуров перед проверкой.
4. Собрать пары (входной DWORD → выходной DWORD) вариацией одного блока (блочная независимость).
   Для каждого блока из пары вида `(0x41414141 -> y)` восстановить скрытый ключ k:
   `k = in ^ (((y * inv(m)) mod 2^32) - C)`.
   В этой задаче восстановленные k давали читаемые фрагменты («Read», «FileW», «TextW», …).
5. Инвертировать формулу для T, получить искомый ввод (55 байт начинается с `DUCKERZ{...}`).

## Грабли
- Отладчик: восстановление `call [rsp+0x80]` занимает 7 байт (`FF 94 24 80 00 00 00`),
  а не 4 — иначе остаток `00 00 00` исполняется как `add [rax],al` → Access Violation.
- Пролог функции нельзя подменять int3 и восстанавливать неправильно; удобнее ставить BP
  на адрес ВНУТРИ функции (после пролога) или использовать аппаратные Dr0/Dr1 (не всегда работают).
- Бинарный ввод с NUL ломает `std::cin >> std::string` — для проверки удобнее
  перезаписывать буфер в памяти в точке перед SF033.
- Формула бизнес-логики: `out = m*((in ^ k)+C) mod 2^32`, инверсия `inv(m) = pow(m,-1,2^32)`.
- Детуры вызываются «по числу процессов»; но блочная независимость всё равно держится.

## Вывод
Задача «reversing + odd winapi» — решается статикой + живым отладчиком + обратной математикой.
Не перебирать 2^32, если есть формула и блочная декомпозиция.

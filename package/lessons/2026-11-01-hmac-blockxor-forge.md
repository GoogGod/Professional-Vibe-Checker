# HMAC: свернутое сравнение (block_xor) — подделка MAC

Суть: проверка HMAC сводится к XOR по блокам (например, 32 байта → 4 байта),
и сервис раскрывает это свёрнутое значение через oracle. Тогда валидный MAC
конструируется тривиально.

## Протокол (типичный)
- `POST /oracle {"msg": ...}` → `{"block_xor": "<8 hex>"}` = XOR блоков HMAC-дайджеста.
- `POST /verify {"msg": ..., "mac": "<64 hex>"}` → флаг при успехе.

## Алгоритм
- `block_xor` = `[xor(digest[0:8]), xor(digest[8:16]), xor(digest[16:24]), xor(digest[24:32])]`.
- Если `find` вернул `target` (4 байта), то берём:
  `mac_in = target[0] + b'\x00'*7 + target[1] + b'\x00'*7 + target[2] + b'\x00'*7 + target[3] + b'\x00'*7`
  (по одному значащему байту на каждый 8-байтовый блок; XOR блока = этот байт).
- Отправляем `{"msg":"give_me_flag_plz", "mac": mac_in.hex()}` → флаг.

## Готовые имплементации
- `toolbox/платформа-limited/hmac_blockxor_forge.py`.

## Почему это работает
- Сравнение идёт не по дайджесту, а по свёрнутому значению — коллизия
  в 4 байтах вместо 32. Классический `CWE-347: Improper Verification of Cryptographic Signature`.

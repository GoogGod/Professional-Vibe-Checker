# Web: mass assignment / NoSQL (MongoEngine __raw__)

Суть: ORM с сырыми операциями принимает пользовательский JSON и позволяет перезаписать
внутренние поля коллекции (класс, роль, идентичность).

## Паттерн
1. Форма регистрации/профиля отправляет JSON, который сохраняется в Mongo.
2. Поля модели добавляются через `__raw__` (MongoEngine) — атакующий передаёт
   `{"$set": {...}}`: оператор обновления выполняется как есть.
3. Ключевая цель — поле дискриминатора `_cls` (или `_id`/роль): подмена класса
   документа (например, на ServiceCard или админ-модель) меняет права и данные,
   видимые на endpoint'ах.
4. Пример сценария: масс-ассайн `_cls` → создание объекта привилегированного типа →
   чтение секретного поля через `/me` / `/api/profile`.

## Чек-лист
- Пробовать операторы Mongo: `$set`, `$unset`, `$push`, `$pull`, `$rename`.
- Пробовать запись `_id`, `_cls`, `scope`, `role`, `is_admin` через сырые поля.
- Искать endpoint'ы, отражающие объект целиком (показывают скрытые поля).
- Проверять, какие классы (модели) существуют: по именам в Swagger/коде/ошибках.

## Итог
- Ошибка типична для MongoDB+ORM «сырые» поля; всегда пробовать $-операторы.
- Поле `_cls`/дискриминатор — цель для смены типа документа.

# Pwn: heap OOB + RLE-overflow + feng shui + ROP (Image Viewer)

Суть: формат изображения с кодированием длин серий (TGA/RLE) и чтением вне границ;
эксплуатация — через контролируемый OOB read/write и массивы чанков.

## Шаг 1. Слабые места формата
- RLE: длина серии (count) не проверяется против размера буфера → переполнение
  при распаковке (copy на N байт туда, где ожидалось меньше).
- OOB read: индексы пикселей/палитры не валидируются → чтение памяти за объектом.

## Шаг 2. Feng shui
- Формат чанков: [P]revious [T]arget [F]ollow — создать чанк перед целью, чтобы
  OOB-read достиг нужного поля (например, указатель на освобождённый чанк).
- Leak PIE/heap через тот же OOB (печать неинициализированных байт в вывод).

## Шаг 3. ROP
- После leak: перезапись возвратного адреса (через write по OOB) → цепочка
  open/read/write (или getdents64 для листинга файлов корня).
- Одна из удобных утилит: флаги лежат в корне; getdents64 перечисляет содержимое.

## Полезно
- При малых размерах загрузки — собирать ROP через читаемые/записываемые сегменты.
- Использовать предложения: `leak` (утечка), `overwrite`, `rop`.

## Итог
- OOB в декодерах изображений = быстрый путь к эксплуатации; связка
  «формат-уязвимость + feng shui + ROP» — рабочий джентльменский набор.

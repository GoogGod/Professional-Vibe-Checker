# RE: Android APK — Bionic rand/seed, XOR-линейный шифр, полный перебор 52^5

Дата: 2026-11-13 (реконструкция), дополнено 2026-11-24 (финальное решение).
Класс: reverse (hard). Статус: РЕШЕНО (подтверждённое решение).

## Суть
APK с нативным JNI-методом `Java_com_example_app_1hard_MainActivity_processInput`
(единственный JNI-экспорт во всех 4 ABI: x86_64/arm64/armeabi-v7a/x86).
Пользователь вводит 5 букв A-Z/a-z; приложение возвращает расшифрованное сообщение.

## Алгоритм (восстановлен по дизассемблеру x86_64 + arm64)
1. Проверка `strlen(input)==5`, все буквы; иначе "No!".
2. 4x `rand()` — мусор, отбрасывается.
3. `ah(input)`:
   - seed = 23869 (0x5D3D);
   - для каждой буквы: `t = seed ^ c; y = ((t<<3) ^ (t>>2)) & 2^64-1;
     seed = (73244475 * y) & 2^64-1` (73244475 = 0x45D9F3B, 64-битное умножение с усечением);
   - `srand((uint32_t)seed)`.
4. 16x `rand() & 0xF` → индекс в алфавит `"abcdef0123456789"` → hex-ключ 16 символов.
5. `dwl(enc, 37, key)`: `out[36-i] = enc[i] ^ key[i%16] ^ 0x5A` (i=0..36)
   ⇔ `out[j] = enc[36-j] ^ key[(36-j)%16] ^ 0x5A`.

## Данные
enc (37 байт, идентичен во всех ABI):
`10 0e 0a 02 09 33 0e 4d 0c 4d 0b 1e 5d 3a 3d 4d 24 33 0b 07 08 2f 3d 0b 1c 0e 4c 5d 03 11 38 6c 28 27 7b 36 7c`

## RNG
Bionic rand()/srand() == glibc random()/srandom() (31-словный аддитивный регистр,
Park-Miller init, 310 шагов прогрева, output = `(state[f]+state[r])>>1 & 0x7FFFFFFF`).
Модель проверена против реального glibc (gcc): полное совпадение на seed
{1, 23869, 123456789, 0xDEADBEEF, 0x80000000, 0xFFFFFFFF}.

## Ловушки (важно!)
- В seed-зацикливании слов: `word % 127773` / `word / 127773` в glibc считаются
  в **signed int32** (а не unsigned) — знаковая семантика обязательна (иначе
  расхождение при seed >= 2^31).
- Индексация ключа в dwl — **циклическая по длине ключа** (mod 16), не по enc.
- Паттерн ключа для префикса формата флага и его суффикса:
  key[0:5] = "76b9b", key[13:16] = "08d" — это жёсткие условия; по ним
  отсекается большинство входов. **Частый баг брута**: путать 15-й символ
  ключа (`'d'`) с `'0'` (симметрия hex-алфавита) → 0 хитов.
- Расшифровка частичная: многие входы дают стабильные блоки `DUCKE` и `1a2b}`,
  но полный флаг собирается только у единственного входа.

## Финальное решение (подтверждено)
Полный перебор всех 52^5 = 380 204 032 входов с критерием «в выводе есть
префикс формата флага и его замыкающий суффикс» даёт **единственный** вход:

- вход: `kvErw`
- ключ: `76b9b68b0eb3708d`
- вывод: флаг `[FLAG]` (строк-шаблон формата флага, 37 символов).

Замечания:
- Значение флага не публикуется в пакете (см. политику).
- Решение воспроизводимо: реализация ah()/dwl() + Bionic RNG + перебор по
  паттерну ключа (или по префиксу вывода) на C (gcc -O3 -pthread) или Python
  с векторизацией; ~380M вариантов — на C это минуты.
- Если перебор даёт 0 хитов — сначала проверить условие 15-го символа ключа
  и знаковую семантику seed-арифметики, затем модель RNG.

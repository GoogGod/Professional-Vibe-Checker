# 2026-10-29 — Диффи-Хеллман: короткий секрет (4 байта) → BSGS

## Задача
- `task.py`: `dh.generate_parameters(generator=2, key_size=512)`, `public_a = pow(g, flag, p)`.
- `out.txt`: p (512 бит), g=2, public_a.
- Подсказка в названии: «4 байта»; «секрет — это и есть флаг, очень короткий».

## Суть
Дискретный логарифм `x = log_g(A) mod p` при ограничении `x < 2^32` (4 байта).
Полный перебор — до 2^32 шагов; BSGS (baby-step giant-step) сводит к O(√N) ≈ 65536 шагов.

## Алгоритм
- m = ⌈√N⌉ ≈ 65536.
- Baby steps: таблица `g^j → j` для j ∈ [0, m) (65536 записей).
- Giant steps: `A * (g^{-m})^i`, i ∈ [0, m]; совпадение с таблицей даёт `x = j + i*m`.
- Обратный элемент: `ginv = pow(g, p-2, p)` (p простое), множитель `gm = pow(ginv, m, p)`.

## Результат
- Валидация на синтетике (секрет 123456) — OK.
- Боевой: `x = 1915974516`; `pow(2, x, p) == public_a` ✓.
- `x.to_bytes(4, 'big')` = `b'r3st'` → флаг `[FLAG]`.
- Little-endian давал `'ts3r'` — нечитаемо; big-endian = правильная интерпретация.
## Урок
- BSGS — дефолтный солвер для «маленького секрета» в DH/ElGamal (лог с ограничением).
- Признак задачи: `public_a = pow(g, flag, p)` + хинт о коротком сообщении.
- Всегда проверяй `pow(g, x, p) == A`; интерпретируй x как big-endian байты (ASCII).
- Скрипт: `toolbox/solve_dh_bsgs.py`.

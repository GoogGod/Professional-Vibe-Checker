# PWN: ограниченный форматный ввод → побайтовая запись
- Дата: 2026-11-10 · Категория: pwn · Статус: решено
- Результат: доказана переносимая схема записи указателя через `printf`-подобный sink при ограниченном алфавите; конкретные значения и адреса не включены.
- Что дано: контролируемая строка форматирования, ограниченный набор допустимых символов и повторный вызов форматного sink; цель — заменить значение функции/хука.
- Цепочка решения:
  1. Проверить, какие спецификаторы реально проходят фильтр; не предполагать, что весь форматный язык доступен.
  2. Определить позицию контролируемого аргумента и подтвердить чтение стековых значений безопасным маркером.
  3. Разложить целевой адрес на байты/полубайты и выбрать `%hhn` или эквивалентную запись.
  4. Упорядочить записи по возрастанию уже напечатанного счётчика; учитывать modulo 256.
  5. Пересчитать padding после каждого запрета символа и проверить длину строки до отправки.
  6. Записать адрес функции по частям, затем вызвать затронутый путь с управляемой строкой.
- Ключевые команды/скрипты: локальный harness должен отдельно проверять фильтр, индекс аргумента, каждую запись и финальный trigger; не смешивать все проверки в один remote-прогон.
- Ловушки/ошибки: `%n` может быть запрещён, но `%hhn` может остаться; форматные спецификаторы и байты payload проходят разные фильтры; один неверный padding портит последующие байты.
- Урок: при restricted alphabet сначала составить таблицу «символ/спецификатор → проходит/не проходит», затем использовать byte-wise writes; адреса и значения вычислять только после подтверждённого leak.
- Теги: #pwn #format-string #arbitrary-write #bytewise

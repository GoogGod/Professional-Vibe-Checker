# SPI / аппаратная инъекция: side-channel PIN + подмена firmware регистра

Суть: hardware-задача «SPI master»: мастер (SPI) опрашивает slave-устройство
(сенсор CORE_TEMP). Флаг появляется после инъекции в регистр сенсора.

## Стадия 1: извлечение PIN по power side-channel
- Сценарий: у нас ограниченное число попыток (attemptsLeft); при вводе
  PIN N загораются «окна» (lit_windows) — индикаторы на плате.
- **Приём**: probe одинаковыми цифрами `[d,d,d,d]` и наблюдать, какие
  окна загорелись → цифра PIN может быть извлечена по числу/позиции
  загоревшихся окон (например, lit_windows=[0,1] для [1,1,1,1]).
- **Rate limit**: сервер отвечает 429 на частые запросы — делать паузы,
  retry с задержкой, не флудить (иначе попытки сгорают).
- Итог: собрать кандидатов по каждой цифре (в примере [1,1,3,4]),
  затем финально подтвердить полный PIN одним точным probe.

## Стадия 2: подмена регистра прошивки через SPI
- `init` возвращает дамп firmware: `DE AD C0 DE 02 01 ... 53 4C 41 56 45 ...`
  — это массив байт: заголовок + регистры.
- Адрес датчика `CORE_TEMP` = `0x08..0x0B` (4 байта).
- Публикуем modified firmware: записываем в регистр `FF FF FF FF`
  (максимальная «температура»).
- Мастер считает температуру критической:
  `CRITICAL TEMPERATURE DETECTED — triggering emergency thermal shutdown`.
  и выдаёт флаг в ответе tick (status / tick-ответ).

## Грабли
- Иногда нужно менять **именно 4 байта регистра**, а не весь дамп.
- Ответ `flash: 200 {"ok":true}` — не финал; флаг придёт следующим
  tick-ом (или в теле ответа на flash).
- Использовать «прошитую» версию, а не просто читать регистры.

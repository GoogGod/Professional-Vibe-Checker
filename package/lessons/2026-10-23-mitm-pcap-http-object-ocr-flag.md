# Урок: MITM-pcap — «важные файлы» это HTTP-объекты; флаг в картинке читает OCR

Дата: 2026-10-23 · Категории: forensics/pcap, ocr · Уровень: easy

## Кейс

- pcap на sll-интерфейсе (снiffer/MITM-хост), 3.6k пакетов, 2 клиента; 90% трафика TLS (нечитаемо) — но `--export-objects http` вытащил артефакты: JPEG 12.8 КБ (`GET /barabulka.jpg`, клиент `127.0.0.1`, Host `s3.bucket.serv` — синтетика MITM-инструмента) + два бинарных блоба POST /we2.
- Приманка-блобы `we2`/`we2(1)` оказались **OCSP-запросом/ответом** (ASN.1 DER: OID, serial, даты `20250701..20250708`) — маркер опознания: читаемые даты и `0R0P0N0L0J0` в начале. Не трогать.
- Флаг был напечатан **в самой картинке** (939×79 — однострочный баннер): `tesseract` решил без стего. JPEG-хвост после FFD9 пуст, steghide пуст — чистая картинка.
- OCR-грабли: psm 7 (single line) прочитал `_` как **пробел** внутри флага. Спасали два режима: `--psm 13` (raw line) и `makebox` (посимвольные боксы) — оба дали `_`. Правило: для однострочных текстов-флагов сверять минимум два режима OCR; пробел внутри `{...}` — почти всегда потерянный `_`.

## Команды-якоря

- `tshark -r x.pcapng --export-objects http,dir -q` — до всякого ручного follow-stream
- Опознание OCSP-мусора: `od -c` → даты Z и DER-структура
- `tesseract img.png stdout --psm 7` / `--psm 13` / `makebox` — тройная сверка однострочных флагов
- Апскейл x3 (PIL LANCZOS) перед OCR мелкого текста

## Связь с базой

- Дополняет host-artifacts-playbook §3 (pcap): при TLS-dominant сначала export-objects по не-TLS протоколам; DNS (`remanga.org`, `polyfill-fastly.io`) — контекст легенды, не пивот.

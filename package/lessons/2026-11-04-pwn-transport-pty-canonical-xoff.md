# PWN: транспортные обёртки — pty canonical mode и scanf-буферизация

Суть: удалённый сервис за pty (canonical) и `scanf`-ввод диктуют
протокол отправки — нарушение ломает эксплойт, а не логику.

## Что это
- `pty` (canonical mode): строки ≤ ~80 байт (MaxCanon), байт 0x13
  (XOFF) останавливает вывод; после строки в 80 байт в очереди остаётся
  «лишний» `\n`.
- `scanf("%Ns")` буферизует: отправка ввода одним куском не даёт
  получить его последующему `read()` — нужно поэтапно отправлять после
  каждого промпта.

## Правила работы
1. Отправлять короткие строки (≤ 80 байт) и дожидаться промпта.
2. Слить «дренаж» `\n` (отправить `\n` и прочитать остаток) перед
   основной стадией.
3. Фильтровать XOFF (0x13) из вывода (не удалять — просто не считать
   его частью данных).
4. Для длинных ROP-цепочек: двухфазный ввод (read#1 → read#2), а не
   одна длинная строка.
5. Если код локально работает, а remote «странный» — сначала проверить
   транспорт: отправить маркер, посмотреть, что вернулось.

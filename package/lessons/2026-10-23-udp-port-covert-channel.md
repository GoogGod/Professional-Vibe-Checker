# Урок: covert channel в UDP-портах (порядок в srcport, данные в dstport)

Дата: 2026-10-23 · Категория: forensics/pcap-covert · Уровень: easy

## Кейс

- pcap 32 пакета, raw-инкапсуляция, один поток 192.168.1.1→192.168.1.2, пустой UDP (ip.len=28). Все IP-поля инвариантны (ID=1, TTL=64) — IP-заголовок исключается.
- Название файла (…IpSpy…) толкало к IP-полям — тупик; «где спрятали» решается выпиской ВСех меняющихся полей: srcport/dstport/checksum/time.
- Декод: `srcport - 30000` = индекс байта (0..31), `32768 - dstport` = значение байта. Диапазоны-подсказки: srcport занимает ровно 30000..30031 (компактный перечислимый диапазон = порядок), dstport ~32643..32720 = 32768 - ASCII (68='D'.. первый пакет «D»).
- Дырка-детект до полного декода: первые 4 отсортированных байта дали «DUCK» — формат совпал с серией задач.

## Команды-якоря

- `tshark -r x.pcap -T fields -e frame.number -e udp.srcport -e udp.dstport` → выписка меняющихся полей
- `sort` по (srcport-база) → `bytes(32768 - dstport)` → `.decode()`
- Обобщённо: любые монотонно-перечислимые поля = индекс; соседнее «странное» поле = payload.

## Связь с базой

- Новый класс для host-artifacts-playbook §3: covert channel по полям заголовков (порты/ID/TTL/timing), когда payload пуст. Имя файла может дезинформировать («IpSpy» → порты, не IP).

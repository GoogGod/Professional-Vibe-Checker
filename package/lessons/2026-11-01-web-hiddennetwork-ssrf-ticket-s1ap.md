# Web → SSRF → тикет → RCE → реплей протокола (multi-stage)

Цепочка: из внешнего веб-приложения дойти до внутреннего сервиса (SSRF), получить
внутренний тикет без проверки владельца и использовать его для RCE, затем повторить
пользовательский протокол поверх специфичного транспорта.

## Шаг 1. SSRF
- Allowed-list по хосту обходится через userinfo в URL:
  `http://allowed@internal:port/` (часть «allowed» — это логин, а не хост).
- Проверять DNS-ребinding, redirect'ы, IPv6/hex-IP, `vps`-обходы.

## Шаг 2. Тикет
- Внутренний API часто не проверяет владельца (owner) — нужен только валидный ID.
- Перебирать/подбирать ID тикетов; проверять методы (GET/POST/PUT) на предмет
  побочных эффектов (например, исполнение команды через subprocess).

## Шаг 3. RCE
- Если API принимает команду (subprocess) — пробовать payload'ы на базе полей,
  которые попадают в shell (find/exec/`$()`).

## Шаг 4. Реплей протокола
- Если между узлами ходит не-HTTP протокол (например, S1AP / TAU поверх SCTP),
  реплей перехваченных сообщений возможен поверх того же транспорта (pysctp и т.п.).
- Сначала понять структуру сообщения: длина, поля, CRC; потом воспроизвести.

## Итог
- Комбинировать SSRF + внутренние API + исполнение команд + протокольные реплеи.
- Не забывать: внутренние сервисы часто доверяют «внутреннему» источнику.

# 2026-11-01 — Радио/DSP: чёрный ящик-трансмиттер (chirp) и эталонный подход

Источник: задача с платформы — задача НЕ доведена агентом
до флага, но методика валидна и переиспользуема.

## Постановка
- Дан `capture.wav` (запись эфира) и бинарный `transmitter` (передатчик).
- Использование: `transmitter FLAG OUTPUT.wav` (payload 8..4096 байт).

## Методика (по шагам)
1. **Эталонная генерация**: прогнать transmitter с известным флагом → получить `test.wav`
   → сравнить структуру с capture (стало понятно, что символы — 2048 семплов, ~42.67 мс).
2. **Спектральный анализ** (numpy): построить спектрограмму, найти тоны (4.2…8.9 кГц)
   → похоже на MFSK/OFDM-подобную схему с chirp-паттернами.
3. **Валидация схемы через эталоны**: меняя длину флага, понять зависимость числа символов
   от длины (нелинейная → есть заголовок/сид).
4. **Дизассемблинг / декомпиляция** (IDA): найти main → кодировщик sub_21ED90,
   чтение `/dev/urandom` (16 байт сид) → модуляция рандомизирована (chirp table строится
   от сида: `(qword_201010[i] - 6000) / 0.042666...` = slope factor).
5. **Вывод**: для рандомизированной модуляции нужно восстановить точный алгоритм
   (или утечку сида), а не только типовые паттерны.

## Переиспользуемые приёмы
- Работа с WAV: `wave` + numpy; `sampwidth=2` → int16; блоки энергии — для поиска символов.
- Символьная решётка: ищи период повторения спектральных паттернов (здесь 2048).
- Если программа-кодировщик дана — используй её как оракул (эталоны) + IDA для внутренностей.
- DSP-анализ удобен на Windows-Python (numpy/scipy); WSL тоже доступен — для установки
  пакетов через pip (--break-system-packages) или запроса оператора на apt.

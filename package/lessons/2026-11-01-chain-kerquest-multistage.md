# Многоэтапные цепочки (multi-stage chain) — методика

Проблема: CTF-таск из 6-10 шагов, где каждый следующий шаг открывается только после решения
предыдущего. Дисциплина экономит часы.

## Общие правила
- Сначала только разведка: внешний вид, имена файлов, структура, magic-байты.
- Пароль архива проверяется РЕАЛЬНОЙ распаковкой (7z t -p..., zip -P ...), а не угадыванием;
  у 7z список имён виден даже у зашифрованного архива.
- Не доверять расширениям: file/hexdump/strings/per start.
- После каждого шага записывать артефакты с именем шага (step01_...).

## Частые приёмы
- PNG/IHDR: сломанная высота → восстановить по CRC32 (байты 16-23 big-endian; CRC по 17 байтам
  начиная с offset 12; перебор height до совпадения CRC).
- WAV: исправить размеры чанков RIFF/data (uf чанков), затем слушать/анализировать.
- Текст в картинках: пазл, штрихкод, leet-подпись; собирать по контексту.
- Fonетика: NATO-алфавит (Tango Hotel = TH) и leet → пароли/пароли.
- Бинарные форматы сжимают текст: strings может не помочь — искать «нарисованный» Base64.
- PCAP: аномалия в номере/размере пакета (например, пакет №1337); извлекать вложенный ZIP.
- OSINT: фото → вывеска → гео → конкретное место → пароль/файл.
- Обфускация JS: искать точку входа в конце, длину флага, валидаторы по позициям
  (напр. 5 функций по 4 символа); восстанавливать XOR-маски, проверять через node.

## Итог
- Каждый шаг даёт «ключ» к следующему: пароль, хэш, адрес, время, слово.
- Развивать привычку фиксировать промежуточные данные (payloads, URL, хэши).

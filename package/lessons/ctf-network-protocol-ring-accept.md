# Сетевой Rust-клиент: протокол с length-prefix, генеративный сервер и кольцо accepted

## Суть кейса
REV-задача: бинарник-клиент (Rust) общается с сетевым сервисом по кастомному
бинарному протоколу. Сервер присылает исполняемый код блоков, клиент исполняет
его локально и возвращает «метку» (u64), по которой сервер выбирает следующий
блок. Цель — достичь блока accepted.

## Ключевые находки

### 1. Wire-формат
- Обе стороны: кадры `[u32 len][тело]`.
- Клиент: hello `[len=4][04 00 00 00]`; решение `[len=20][u32 1][u64 block_id][u64 label]`.
- Сервер:
  - BlockImage: `[u32 var=0][u64 id][u64 ilen][code][u8 cache]`;
  - ответ на решение: `[u32 var=1][u64 next_block][u64 len][code][u8 cache=1][u64 pending]`;
  - reject: `[u32 4]`.
- Сервер генеративен: запрос `[len=12][u32 2][u64 id]` возвращает код ЛЮБОГО блока.

### 2. Граф диалога
- У клиента статическая таблица рёбер (block_id + label) -> следующий блок.
- Блоки — небольшие нативные функции (call через VirtualAlloc RWX + FlushInstructionCache).
  Паттерн кода: `mov rax,[rcx+off]; cmp/xor byte [rsi+idx],K; movabs rcx,EQ; movabs rax,NE; cmove; ret`.

### 3. Кольцо accepted
- Обычный путь ведёт в wrong. Кольцо из 18 блоков имеет вход 0x580c и выход
  0x2b46 (блок печати accepted). Входа в кольцо из обычного графа нет
  (0x580c не имеет рёбер-родителей).
- Если известны метки «внутрь» всех блоков кольца, можно пройти всё кольцо
  напрямую в диалоге с сервером: на каждый ответ сервера слать решение
  [1][block][label_inside]. Сервер послушно ведёт по кольцу до accepted-блока.

### 4. Ловушка клиента
- Подсунуть клиенту чужой блок кольца (0x580c) в любом формате (var=0/1,
  cache=0/1) нельзя: клиент падает с 0xC0000005 (AV) — блок опирается на
  образ/контекст фрейм-стека, который в его обычном диалоге не подготовлен.
- Для того чтобы клиент сам напечатал accepted, нужен патч бинарника
  (подмена диспетчера/таблицы рёбер).

## Выводы
- Для «сдачи» достаточно достичь accepted-блока: диалог с сервером завершается
  принятием (проверяемо).
- Если требуется вывод самого клиента — патч одного из диспетчеров.
- Сначала пробуй идти через серверные переходы (генеративный сервер) —
  это быстрее, чем патчить клиента.

## Инструменты
- Python sockets + struct для диалога; скрипт прохождения кольца (см. сессию).
- IDA headless для декомпиляции обработчика ответов и исполнителя блоков.
- Логирование всех фреймов в файл — критично для восстановления протокола.

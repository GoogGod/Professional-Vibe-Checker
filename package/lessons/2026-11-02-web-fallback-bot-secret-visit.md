# 2026-11-02 Web: fallback-секрет бота + /api/visit → приватная заметка

## Суть
- Бот-проверяльщик ссылок (`/api/visit` принимает URL и «посещает» его) в своём
  клиентском JS-коде имеет **fallback-идентификатор** (жёстко прописанный UUID),
  который используется, когда сессия/авторизация не подгружена.
- Если этот UUID принадлежит «юзеру с правами» (например, админу), то при
  подмене/копировании его в куки/заголовок и открытии приватной заметки
  (обычно — единственного приватного документа) она отдаётся.

## Признаки
- В JS-бандле бота встречаются постоянные UUID/hex-идентификаторы рядом с
  логикой `fetch('/api/...')` и обращением к приватным маршрутам.
- Сервер принимает идентификатор из запроса без проверки подлинности
  (доверяет клиенту): примета — «идентификатор в query/куках работает без логина».

## Шаги
1. Скачать JS бота (статика с главной страницы), поискать UUID/hex-константы
   (`[0-9a-f]{8}-[0-9a-f]{4}-...`, длинные hex).
2. Сверить найденный UUID с публичными «профилями» (напр., `GET /api/users/<id>`),
   найти, к какому пользователю относится, и какие у него заметки/документы.
3. Повторить запрос `GET /api/notes`/`/documents` с этим UUID в куках/токене
   (или подменить в сессии) — получить приватную заметку.
4. Если есть `POST /api/visit`, сначала убедиться, что отдаваемый ей контент
   нигде не валидируется (это путь к XSS/SSRF, но здесь для идентификации не нужен).

## Грабли
- Не всегда нужен XSS через visit: достаточно «слепого» использования UUID
  (Fallback-токен) — проверять ОБА пути.
- Иногда ID бота не UUID, а числовой (инкремент) — перебирать малые диапазоны
  (0..1000) против `/api/users/<n>`.
- Флаг обычно в теле приватной заметки (единственной), не в общем списке.
